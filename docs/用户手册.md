# PetDeck 用户手册

PetDeck 是一只住在桌面角落的 Agent 宠物：它聚合你本机 AI Agent（Codex、Claude Code、opencode、Kimi）的「项目→任务→会话」状态，没事时安静待在余光里，Agent 干完/卡住/等拍板时才轻拍你；任务要交给下一个 Agent 时，它自动打包上下文 + 产物 + 指令，一键确认完成交接。

你的会话内容与缓存全部留在本机，不会上传到任何服务器；遥测只记录行为事件（如「发生了一次接力」），不记录内容。

## 1. 安装

从 GitHub Releases 下载 NSIS 安装包（`PetDeck_x.y.z_x64-setup.exe`），双击安装即可。安装器会自动检查并安装 Microsoft Edge WebView2。

系统要求：

| 项 | 要求 |
| --- | --- |
| 操作系统 | Windows 10 / 11 |
| WebView2 | 缺失时安装器自动下载 |
| Node.js | 24 或更新版本（PetDeck 借用它运行本地 bridge；未安装时宠物会明确报错） |
| Agent CLI | 可选；缺哪个就只少哪张卡片，不影响其它 Agent |

## 2. 首次运行

启动后桌面上会出现宠物小窗，bridge 会自动在后台启动（随机 token、自动选端口，无需手动配置）。单击宠物可展开项目摘要、免打扰收件箱和主面板入口；拖动宠物顶部的手柄可以挪位置，位置会被记住。

关闭宠物窗或主面板只是隐藏，从托盘「退出」才会真正结束应用并回收 bridge。

## 3. 接入 Agent

打开主面板 → 接入页，选择 Agent 类型并检测：

- **Codex**：需要本机安装 `codex` CLI。PetDeck 读取 `~/.codex/sessions` 会话记录；`codex exec` 注入目前是实验能力，失败会自动降级为剪贴板交接。
- **Claude Code**：读取 `~/.claude/projects/*.jsonl`；注入使用 headless `claude -p --output-format stream-json`。
- **opencode**：观察依赖本地 `opencode serve`（默认端口 4096）。注入走 `opencode run`。
- **Kimi（kimi work）**：托管网页 Agent，仅支持观察；接力恒为剪贴板交接。

能力分级说明：full = 可读可注入；observe-only = 只能看；manual = 一律剪贴板。检测失败（拒绝/限流）时会给出内联错误与手动降级路径。

## 4. 日常使用

**余光看状态**：宠物身体的颜色/形态表示聚合状态，计数 badge 显示运行中/完成/等待。免打扰开启时，非「等你拍板」事件静默进入收件箱，等你点开或关闭免打扰时批量补提示，不会丢。

**接力（核心功能）**：当某个会话完成且需要交棒时，点「接力」→ 预览自动打包的上下文 + 产物 + 指令（可编辑、可删产物）→ 确认发送。全程 ≤3 步。目标 Agent 不支持注入时，交接包自动变为可复制的文本（manual 模式），粘贴到对方输入框即可。断网时交接包会本地暂存，不丢。

**免打扰**：托盘菜单或宠物快捷设置里开关。开启后只有「等你拍板」的事件会轻拍。

**自动更新**：右键宠物 →「宠物设置」→「自动更新」。打开设置时会自动检查一次 GitHub Releases；发现新版本后显示版本号，点「安装并重启」才会下载安装。更新包经过签名校验，下载完成后应用会自动重启到新版本。

**语言 / Language**：右键宠物 →「宠物设置」→「语言」，可切换中文 / English。应用界面与系统托盘菜单会即时切换，选择保存在本机；首次启动跟随系统语言。

**宠物成长**：宠物会随着你使用 Agent 一起成长。完成 Agent 任务或接力 +10 经验，抚摸宠物 +2 经验（30 秒冷却）；连续使用的天数会累计。展开宠物快捷面板可看到等级、称号、进度条与完成任务数，主面板标题栏也会显示等级。成长只做陪伴反馈，不设饥饿或衰减惩罚。

**跨机器会话（SSH）**：如果你在另一台机器上跑 Agent，可设置环境变量 `PETDECK_REMOTE_HOSTS=me@build-box`（多个主机用逗号分隔）后重启 PetDeck。远程主机的 Claude Code / Codex 会话会以只读形式显示，带 `@host` 标记，不会误把接力发到本机；远程会话不能接力或注入。需要本机已配置 SSH 免密登录，远程有 `node`。详见 `docs/远程会话.md`。

> v0.1.0 未内置更新器，需要手动安装一次 v0.1.1；之后即可在应用内更新。

## 5. 故障排查

| 现象 | 原因与处理 |
| --- | --- |
| 宠物显示「Node 缺失/版本过低」 | 安装 Node.js 24+（https://nodejs.org），然后重启 PetDeck |
| 宠物显示 bridge 启动失败 | 查看错误提示中的具体原因；bridge 只绑定 127.0.0.1，不与其它应用抢端口（桌面版自动选可用端口） |
| 连接显示「离线/重连中」 | bridge 进程异常退出会自动重启；若持续离线，检查杀毒软件是否拦截 Node 子进程 |
| 状态长时间不更新（stale 标记） | 对应 Agent 的会话目录暂时不可读（如被占用）；PetDeck 保留最后已知状态并标记新鲜度，恢复后自动续上 |
| opencode 卡片无数据 | 确认本地已运行 `opencode serve`（默认 `http://127.0.0.1:4096`） |
| 注入一直降级剪贴板 | 对应适配器的注入链路失败（如 CLI 版本兼容问题）；剪贴板交接是设计内的降级路径，不是故障 |
| 检查更新失败 | 确认能访问 GitHub Releases；若当前版本是 v0.1.0，应用内更新尚不可用，请手动安装 v0.1.1 |
| 安装更新后仍是旧版本 | 安装器会退出应用再启动新版本；若被安全软件拦截，手动运行下载的 NSIS 安装包 |
| 数据存在哪里 | 全部在本机：会话内容只从各 Agent 的本地文件/服务读取；PetDeck 自身的缓存与设置在用户数据目录，不上传 |

**隐私红线**：会话内容与缓存全部留在本机；埋点只报行为事件、不含内容；bridge 仅监听 127.0.0.1，且读取/注入均要求前端持有的随机 token 与白名单 Origin，本机其它进程无法读取你的会话。
