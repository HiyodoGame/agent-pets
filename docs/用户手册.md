# PetDeck 用户手册

> 适用于 PetDeck 下一版（M5 打磨版；本文档快照 2026-11-21）。本版是文字手册，**暂无截图**；界面以侧栏、卡片和按钮上的中文名称为准，English 界面使用对应英文。
>
> 手册按“安装 → 接入 Agent → 建任务 → 验收 → 合并 → 看日报 → 导出诊断”的顺序编写。每一步都给出预期结果；如果你的界面与描述不同，先看第 9 节故障排查，或在[真机实测矩阵](真机实测矩阵.md)里核对已知差异。

## 0. 五分钟走通

| 步骤 | 做什么 | 预期结果 |
| --- | --- | --- |
| 1 | 安装并启动 PetDeck | 桌面出现宠物小窗，托盘出现 PetDeck 图标 |
| 2 | 托盘 →「打开主面板」→ 设置 | 「运行时」卡显示版本、内置 Node、端口和数据库版本 |
| 3 | 今日 →「登记项目」 | 项目出现在项目页和今日页 |
| 4 | 今日 →「新建任务」→ 填写 → 创建 | 进入任务页，状态为「待开始」 |
| 5 | 任务页 →「开始」 | 状态变为「运行中」，实时会话开始出现事件 |
| 6 | 任务完成 → 验收 | Git 项目进入「待合并」；普通目录直接「已完成」 |
| 7 | Git 项目 → 生成合并授权 → 确认合并 | 分支合入主分支，状态变为「已合并」 |
| 8 | 汇报 → 生成今日日报 | 出现当天任务汇总；配置经理模型后由模型撰写 |
| 9 | 设置 →「导出诊断包」 | 显示文件数、大小与 zip 路径 |

> 第 5 步不会自动开始：创建任务只是登记，确认说明和 Agent 后再点「开始」，避免误派发。

## 1. 安装与首次启动

### 1.1 系统要求

| 项 | 要求 |
| --- | --- |
| 操作系统 | Windows 10 / 11，64 位 |
| WebView2 | 缺失时由安装器自动下载安装 |
| Node.js | **无需单独安装**：安装包内置官方 Node.js 24.18.0 |
| 磁盘 | 安装后约 107 MB；运行记录、产物和 worktree 会继续增长 |
| Agent CLI | 可选；只有你想把任务派给某个 Agent 时才需要安装它 |
| 网络 | 安装/更新需要访问 GitHub Releases；Agent 本身按各自的网络要求工作 |

源码开发需要 Node.js 24+，详见 [petdeck/README.md](../petdeck/README.md)；普通用户不需要装 Node。

### 1.2 安装

1. 从 [GitHub Releases](https://github.com/HiyodoGame/agent-pets/releases) 下载最新的 `PetDeck_x.y.z_x64-setup.exe`。
2. 双击安装包，按向导完成安装。安装器会在需要时安装 WebView2。
3. 安装完成后启动 PetDeck。

预期结果：桌面出现宠物小窗，托盘出现 PetDeck 图标；首次启动不需要配置端口或令牌，本地服务会自动启动。

> 安装包内置 Node 运行时，因此干净机器不需要预先安装 Node。若安装目录里的内置运行时被删除或损坏，界面会提示“安装可能不完整，请重新安装 PetDeck”，而不是让你去装 Node。

### 1.3 首次启动检查

1. 在托盘图标上右键，选择「打开主面板」。
2. 打开左侧「设置」。
3. 看最上面的「运行时」卡。

预期结果：

- 应用版本为当前安装版本（以设置页显示为准）；
- Node 运行时显示 `v24.18.0`；
- 本地端口显示 `127.0.0.1:xxxxx`；
- 数据库版本为 4，已运行时间会持续增加；
- 数据目录和日志目录各有一行路径，可点旁边的复制按钮；
- Agent 探测表列出适配器；已安装的 CLI 显示“已检测到 + 版本”，未安装的显示“未找到”。

如果这里显示“本地服务未启动”，按第 9.1 节处理。

### 1.4 数据放在哪里

| 内容 | 默认位置 |
| --- | --- |
| 数据库、运行记录、产物、日志 | `%APPDATA%\PetDeck` |
| 任务使用的 Git worktree | `%LOCALAPPDATA%\PetDeck\worktrees` |
| 诊断包 | 系统临时目录下的 `petdeck-diag-*` |
| 项目源码 | 你登记项目时选择的原目录，PetDeck 不复制源码 |

关闭宠物窗或主面板只是隐藏窗口；从托盘选择「退出」才会结束应用并回收本地服务。

## 2. 界面总览

### 2.1 两个窗口

- **桌宠小窗**：常驻桌面角落，显示聚合状态。单击展开快捷面板，拖动可移动，位置会被记住。
- **控制台**：完整的管理界面，包含今日、任务、项目、Agent、汇报和设置。

托盘菜单中的「打开主面板」打开控制台；右键宠物也有「打开控制台」。

### 2.2 控制台导航

左侧栏分两组：

| 分组 | 页面 | 用途 |
| --- | --- | --- |
| 控制台 | 今日 `/today` | 决策、统计、观察会话、经理和任务预览 |
| 控制台 | 任务 `/tasks` | 按状态排列的任务板 |
| 控制台 | 项目 `/projects` | 登记和管理项目目录 |
| 控制台 | Agent `/agents` | 运行时 Agent 能力与只读观察源状态 |
| 控制台 | 汇报 `/reports` | 每日/按项目汇总 |
| 控制台 | 设置 `/settings` | 运行时、存储、调度、经理模型、更新 |
| 旧版 | 会话 / 接力 / 连接 / 伙伴 | 旧版观察与交接入口，本手册不展开 |

侧栏底部可以切换演示模式、深色/浅色外观，并显示陪伴成长等级。

### 2.3 连接状态

顶栏会显示「实时」「重连中」或「离线 · 截至 {时间}」。离线时页面顶部还会出现「本地会话服务未启动」或「当前离线」横幅和「重连」按钮。

本地服务是控制台与 Agent 之间的桥梁，只监听本机回环地址。它退出后，控制台仍能打开，但读不到新任务和事件；按第 9.1 节恢复。

## 3. 接入 Agent

PetDeck 里 Agent 分两类：**可派发任务的运行时 Agent** 和**只读观察的会话来源**。这两类不能混用：观察会话不会出现在任务板里，也不能验收或合并。

### 3.1 可派发任务的运行时 Agent

当前只有三个运行时适配器：

| Agent | 命令 | 适合做什么 |
| --- | --- | --- |
| Claude Code | `claude` | 代码修改、需要权限决策和会话续接的任务 |
| Kimi Code | `kimi` | 代码任务与会话续接 |
| opencode | `opencode` | 代码任务；运行结束不保留后台守护进程 |

接入步骤（以 Claude Code 为例）：

1. 在 PowerShell 里运行 `claude --version`，确认命令存在且能输出版本。
2. 在同一个终端里完成登录/配置，确保 `claude` 能直接执行任务。
3. 重新打开 PetDeck（或设置 → 运行时 →「重启本地服务」）。
4. 打开 Agent 页，确认对应卡片显示“可用”。
5. 打开设置 → 运行时，在 Agent 探测表里确认该命令为“已检测到”。

预期结果：新建任务对话框的「Agent」下拉框里能选到它；任务开始后，实时会话出现事件。若探测为“未找到”，先确认命令在 PATH 中，再重启本地服务。

### 3.2 只读观察的会话来源

这些 Agent 的本地记录会被聚合到今日页「观察中的会话」，但**只能看**：

| 来源 | 读取位置 |
| --- | --- |
| Cursor | `~/.cursor/projects` |
| DeepSeek Harness | `~/.dsh/sessions` |
| zcode | `~/.zcode/cli/db`（只读临时副本） |
| Gemini CLI | `~/.gemini/tmp` |
| Kimi（托管） | 旧版观察层 |
| Kimi Code 旧库 | `~/.kimi/sessions` |
| Remote SSH | 由 `PETDECK_REMOTE_HOSTS` 指定 |

使用步骤：

1. 先在对应工具里正常开始一个会话。
2. 回到今日页，等待最多约 10 秒（观察源每 5 秒轮询一次）。
3. 在「观察中的会话」里确认出现标题、项目和相对时间。

预期结果：最多显示 5 条；点「查看全部」可打开只读抽屉，左侧选会话，右侧看最近 20 条转录。转录会去掉 Markdown 标记、标签和隐藏推理，只显示可读文本。

> 观察会话不能注入、不能验收、不能合并，也不会进入任务板或汇报统计。这是设计上的隔离，不是权限故障。

### 3.3 远程 SSH 会话

1. 确认本机已配置 SSH 免密登录，远程机器上有 `node`。
2. 设置环境变量 `PETDECK_REMOTE_HOSTS=me@build-box`；多个主机用逗号分隔。
3. 重启 PetDeck。
4. 打开今日页的观察区，确认出现带主机标记的会话。

预期结果：远程会话以只读形式显示，不能派发任务。更多边界见[远程会话](远程会话.md)。

### 3.4 Codex 与其他未接入项

Codex 控制台托管尚未接入：app-server 协议需要网络代理，Agent 页会显示“暂缓”。不要把它当作可建任务的 Agent；旧版 `/panel` 可能仍能观察 Codex 会话，但这不属于本手册的推荐流程。

## 4. 项目、任务与今日页

### 4.1 登记项目

1. 今日页右上角点「登记项目」，或在项目页点「登记项目」。
2. 选择一个本地目录。
3. 确认。

预期结果：项目卡片出现，并标明是「Git 仓库」还是「普通目录」。Git 仓库的任务会在独立 worktree 中运行；普通目录直接在该目录运行。

> 一个项目对应一个本地目录。目录移动后请重新登记，避免任务和 worktree 指向旧路径。

### 4.2 新建任务

1. 今日页点「新建任务」。
2. 选择项目。
3. 填写标题和任务说明。说明要写清楚目标、约束、验收标准，以及要不要跑测试。
4. 选择 Agent。
5. 选择权限模式：

| 模式 | 含义 |
| --- | --- |
| 自动接受编辑 | Agent 可以改文件，不再逐次询问编辑权限 |
| 每次询问 | 遇到需要权限的操作时生成决策卡，等你回答 |
| 只做计划 | 只输出计划，不直接改代码 |
| 跳过权限检查 | 跳过全部权限确认，风险最高，只在隔离环境使用 |

6. 可选：勾选依赖任务。依赖未完成时，本任务不会开始。
7. 点「创建」。

预期结果：进入任务页，状态为「待开始」。此时还没有运行；确认内容无误后点「开始」。

### 4.3 今日页

今日页回答“现在谁在干活、哪里卡住了”：

- 顶部决策横幅：有等待你拍板的问题时出现，可直接「去回答」。
- 统计 7 项：运行中、排队中、需处理、待验收、待合并、已暂停、已完成。
- 观察中的会话：外部工具的只读会话，最多 5 条。
- 经理面板：用自然语言拆解任务，提案必须你确认。
- 任务栏与右侧预览：按进行中、待开始、排队中、待你处理、已结束分组；点任务可在右侧看说明和最近动态，再打开任务页。

### 4.4 用经理拆解任务

1. 先在设置 →「经理模型」里填好服务地址、模型名和 API 密钥，并点「测试连通」。
2. 回到今日页的经理面板。
3. 选择项目。
4. 输入目标，例如“给这个项目加一个健康检查接口，并补一条测试”。
5. 点发送。
6. 在提案卡里检查任务数量、标题、说明、验收标准、Agent 和依赖；需要时点「调整」。
7. 点「确认派发」。

预期结果：任务被创建并出现在今日页/任务板，是否立即运行仍由调度和你的「开始」决定。经理只负责拆解、解释和汇总；派发、合并、停止都必须由你在界面确认。

若经理模型未配置或调用失败，今日页仍可使用手动建任务；日报会退回本地汇总。

### 4.5 任务板

任务板按状态分列：待开始、排队中、运行中、待拍板、已暂停、待验收、待合并、需处理（失败/已停止）、已完成（已完成/已合并）。点任意卡片进入任务页。

### 4.6 任务页

任务页顶部是状态与动作，下面是验收/合并面板、决策卡、实时会话和右侧任务信息。

常用动作：

- 运行中：暂停、停止。停止会结束本次运行，不一定保留会话。
- 已暂停：继续、停止。
- 排队中：停止（取消排队）。
- 待开始/已停止/失败：开始或重试；有会话时可「续接」。
- 待验收/待合并：没有顶部运行动作，按面板处理。
- 已合并/已完成：有 worktree 或分支时可「清理 worktree」。

实时会话默认显示最近 2000 条事件。向上滚动会自动加载更早的事件；离开底部后，新事件会以计数提示，点「回到最新」回到实时跟随。事件很多时这是正常的窗口化行为，不是丢数据。

### 4.7 决策卡

Agent 需要你选择时，今日页顶部和任务页会出现决策卡。

1. 读问题与选项。
2. 选择一个选项，或填写自定义回答。
3. 提交。

预期结果：回答写回同一个运行/会话，Agent 继续工作；决策卡从待处理列表消失。

### 4.8 排队、并发与依赖

设置 →「调度与决策」里的「并行上限」控制同时运行的任务数（1–8）。达到上限后，新任务进入「排队中」，状态横幅会说明“有 Agent 结束后会自动开始”。

依赖任务全部完成后，本任务才会从排队进入可运行。若一直不开始，先看并行名额和依赖状态，而不是反复点「开始」。

### 4.9 本地服务重启后的中断恢复

如果任务运行期间本地服务崩溃或被重启，任务页/今日页会出现中断横幅：

> 上次运行被本地服务重启中断（{时间}）。

处理方式：

- 点「继续（同一会话）」：尽量用原会话续跑，适合还能接上的任务。
- 点「放弃这次运行」：隐藏本次提示，之后可手动「开始/重试」。
- 没有会话 ID 时「继续」不可用，只能重新开始。

## 5. 验收、打回、合并与清理

### 5.1 产物

任务运行过程中，PetDeck 会收集工作目录里的图片、视频、音频、PDF 和普通文件，显示在任务页「产物」区。你可以预览、下载、手动添加或移除产物。产物是验收证据，不是自动合并的内容。

### 5.2 验收

任务进入「待验收」后，任务页出现「这一轮完成了」面板：

1. 读「本轮总结」。
2. 检查「本轮产物」。
3. 如果结果符合要求，点「通过验收」。

预期结果：

- Git 项目：任务进入「待合并」，不会自动改主分支。
- 普通目录：任务直接变为「已完成」。

### 5.3 打回重做

1. 在验收面板点「打回」。
2. 填写打回意见（必填），写清楚哪里不对、要改成什么。
3. 选择交给哪个 Agent。
4. 点「提交打回」。

预期结果：生成一次新的运行，尽量续接同一会话，任务回到运行中；打回次数会记录在任务上。

### 5.4 合并到主分支

只有 Git 项目会进入「待合并」。

1. 打开任务页的「合并到主分支」面板。
2. 核对分支、目标分支、提交和变更摘要。
3. 点「生成合并授权」。授权 10 分钟内有效。
4. 点「确认合并」，在确认框中确认。

预期结果：分支以 `git merge --no-ff` 合入目标分支，任务变为「已合并」。PetDeck **不会 push**，远端仓库不会变化。

如果提示冲突、主仓库有未提交改动、或当前不在目标分支：先按提示清理/切换主仓库，再重新生成授权并合并；也可以放弃合并。

### 5.5 放弃合并与清理

- **放弃合并**：任务标记为完成，主分支不变，分支和 worktree 仍在，之后可清理。
- **清理 worktree**：删除任务使用的 worktree 和分支。确认框会说明已合并的提交不受影响；未合并的改动会丢失，清理前先确认。

## 6. 汇报

1. 打开左侧「汇报」。
2. 选择「全部项目」或某个项目。
3. 点「生成今日日报」或「生成日报」。

预期结果：出现当天的任务统计（涉及任务、完成、待验收、待合并、需处理、待决策）和文字汇总。配置了经理模型时标记为经理模型生成，否则标记为本地汇总。

汇报只统计运行时任务，不包含观察会话。

## 7. 设置

设置页从上到下依次是：运行时、存储、调度与决策、经理模型、关于与更新。

### 7.1 运行时

- 查看应用版本、内置 Node 版本、本地端口、数据库版本、已运行时间和密钥存储状态（DPAPI 加密 / 未加密 / 无法解密）。
- 复制数据目录、日志目录。
- 查看 Agent 探测表：每个适配器的命令、是否检测到、版本。
- 「导出诊断包」：见第 9.3 节。
- 「重启本地服务」：会重新生成令牌，其它窗口会自动重连；正在运行的任务可能被中断，随后用中断横幅续接。
- 「Node.js 许可」：打开内置 Node 的 LICENSE 与 THIRD_PARTY_LICENSES。

若这里有崩溃警示、数据库重建备份路径、上次中断运行数或「密钥未加密/无法解密」警示，按第 9.4/9.5 节处理。

### 7.2 存储

显示日志、运行记录、产物、数据库、合计占用和最早一份运行记录的时间。

点「清理旧运行记录」只会删除超过 30 天未更新的运行记录文件（`runs/` 下的 `events.jsonl` 等），任务索引和事件数据库保留。清理前确认没有需要回看的旧会话。

### 7.3 调度与决策

- 并行上限：1–8。
- 决策卡超时：1–720 分钟。
- 新决策提示音：开关。
- 修改后点「保存」。

### 7.4 经理模型

经理只负责拆解、解释与汇总；派发、合并、停止都必须由你在界面确认。

填写：

1. 服务提供方（OpenAI 兼容服务或本地 Ollama 等）。
2. 服务地址。
3. 模型名。
4. 温度（0–2，默认 0.3）。
5. 超时（5000–600000 ms）。
6. API 密钥；留空表示不修改，已有密钥可清除。
7. 点「测试连通」，成功后再「保存」。

密钥使用 Windows DPAPI 加密后保存在本机数据库（`%APPDATA%\PetDeck\petdeck.sqlite`），只有当前 Windows 用户可解密；系统不支持 DPAPI 时设置页会标注「未加密」并明文保存。密钥不会随诊断包导出。若服务不可达，经理功能会报错，但手动建任务不受影响。

### 7.5 关于与更新

- 显示当前版本。
- 「检查更新」会访问 GitHub Releases。
- 有可用版本时显示版本号和更新说明。
- 「安装并重启」会下载、验签并安装；下载时显示进度条。
- 有任务运行时只提示、不强制阻止，建议等任务结束再安装。
- 失败时按网络不可达、签名校验失败、磁盘写入失败分类显示，可重试或「从 Releases 手动下载」。

应用内更新只对安装版生效；源码运行请用构建流程。发布与回滚细节见[自动更新与签名](自动更新与签名.md)。

## 8. 桌宠、托盘与外观

- 单击宠物：打开快捷面板，优先显示任务、项目摘要、静默收件箱、打开控制台和宠物设置。
- 拖动宠物：移动位置，重启后保持。
- 右键宠物：打开控制台、免打扰开关、宠物设置、隐藏宠物、退出 PetDeck。
- 托盘：显示宠物、打开主面板、本地服务状态（例如「本地服务：运行中 · :5199」）、重启本地服务、免打扰、开机启动、退出。

宠物设置里可以改皮肤、动效（跟随系统/完整/减弱/关闭）、尺寸、漫步、置顶、语言（中文/English/跟随系统）和自动更新。开启「减弱动效」或系统开启减少动态效果后，桌宠和面板动画会降级。

通知只在 Agent 开始、完成、卡住或等待拍板等状态变化时提醒，不显示会话正文。开启免打扰后，非「等你拍板」的提醒会静默进入收件箱，关闭免打扰时批量补提示。

## 9. 故障排查

### 9.1 控制台显示离线或「本地会话服务未启动」

1. 看托盘菜单的「本地服务」状态。
2. 打开设置 → 运行时，点「重启本地服务」。
3. 等几秒，点顶栏「重连」或刷新页面。
4. 仍失败，打开 `%APPDATA%\PetDeck\logs\sidecar-*.log`，搜索 `bridge.` 开头的记录。

常见原因：

- 内置 Node 运行时缺失/损坏：日志出现 `bridge.node_unavailable`，应重新安装 PetDeck。
- bridge 脚本缺失：日志出现 `bridge.script_missing`，应重新安装。
- 端口被占用：桌面版会自动选择端口，以设置页显示的端口为准。
- 杀毒软件拦截子进程：把 PetDeck 安装目录加入信任后重启应用。

### 9.2 Agent 探测为「未找到」或任务立即失败

1. 在 PowerShell 里运行对应命令：`claude --version`、`kimi --version`、`opencode --version`。
2. 确认命令能执行并已登录。
3. 重启 PetDeck，或设置 → 运行时 →「重启本地服务」。
4. 打开任务页，查看实时会话里的 `stderr` 和失败原因。

预期结果：Agent 探测变为“已检测到”，新任务可以启动。安装包不带 Agent CLI，需要你自行安装。

### 9.3 导出诊断包

1. 设置 → 运行时 →「导出诊断包」。
2. 等待生成。
3. 复制显示的 zip 路径，用资源管理器打开。

预期结果：显示「已生成诊断包（n 个文件，size）」；包内有 `summary.json`、`settings.json`、`agents.json`、`environment.json` 和最近 7 天的 `logs/`。设置只导出白名单字段，密钥和 prompt 全文不会写入。

### 9.4 更新失败

| 提示 | 处理 |
| --- | --- |
| 网络不可达 | 确认能访问 GitHub Releases；检查代理/防火墙后重试 |
| 签名校验失败 | 安装包可能损坏或被篡改；不要绕过校验，点重试或从 Releases 手动下载 |
| 磁盘写入失败 | 清理磁盘空间、检查安装目录权限，关闭安全软件拦截后重试 |
| 安装后还是旧版本 | 安装器会退出应用再启动；若被拦截，手动运行下载的 NSIS 安装包 |

升级前建议先结束正在运行的任务，并在设置里导出一次诊断包。

### 9.5 数据库损坏或重建

如果启动时检测到数据库损坏，PetDeck 会把原文件备份为 `petdeck.sqlite.bak-<时间>`，然后新建一个空库。

1. 打开设置 → 运行时，确认页面显示备份路径。
2. 若任务列表为空，这是重建后的预期结果。
3. 需要找回旧数据时，先退出 PetDeck，再联系维护者处理备份，不要在两个进程同时运行时直接替换数据库。

### 9.6 观察会话为空或转录不可读

- 确认对应的外部工具确实产生过会话。
- 今日页观察区每 8 秒刷新，最多显示 5 条；点「查看全部」看完整列表。
- 打开 Agent 页，看该来源的「最近写入」「成功/失败」「最近错误」。
- zcode 等来源只提供会话元数据时，抽屉会说明不支持逐行读取；这是预期行为。

### 9.7 清理 worktree 失败

通常是编辑器、终端或文件索引仍占用 worktree 目录。关闭占用该目录的程序后重试；不要手动删除主仓库的分支引用。

## 10. 数据、隐私与卸载

PetDeck 的本地服务只监听 `127.0.0.1`，使用随机令牌和 Origin 白名单；会话内容、任务说明、产物和缓存留在本机，不上传到 PetDeck 的服务器。诊断包会做字段白名单和密钥掩码。

- 日志保留 7 天，单个文件超过 5 MB 会轮转。
- 运行记录默认保留 30 天，可在设置 → 存储清理。
- 数据库损坏时会保留 `.bak-<时间>` 备份。
- 卸载程序不会自动删除 `%APPDATA%\PetDeck` 和 `%LOCALAPPDATA%\PetDeck\worktrees`；如需彻底清除，先确认没有要保留的运行记录，再手动删除这两个目录。
