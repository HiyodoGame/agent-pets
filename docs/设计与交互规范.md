# PetDeck 设计与交互规范

本文定义当前产品界面的设计基线。它取代此前围绕具体页面草案形成的布局限制，业务适配器、数据安全和接力语义仍遵循现有工程契约。

## 1. 产品体验原则

### 宠物优先

桌宠是常驻主体，面板是临时工作区。任何快捷面板、事件卡、右键菜单和设置页都不得覆盖宠物的可见区域。打开主窗口时，也要主动避开宠物。

### 先处理，再浏览

会话首页优先呈现等待用户处理的事项，其次是运行状态和普通项目信息。页面只保留一个主要视觉入口，不使用同权重卡片堆叠来制造层级。

### 安静但可理解

默认状态保持克制。状态不能只依赖颜色，必须同时有文字、图标或可访问名称。离线、缓存、演示和真实发送结果必须明确区分。

### 操作就近

高频操作放在当前对象附近。外观、演示数据和连接状态属于应用级控制，不与会话操作混排。次级和破坏性操作进入对象菜单，不占用主行动线。

## 2. 信息架构

主导航固定为四类任务：

1. 会话：项目索引、会话列表、看板和线程。
2. 接力：选择来源、编辑交接内容、追踪结果和完成回执。
3. 连接：发现 Agent、检测能力、授权和首次同步。
4. 伙伴：真实状态、外观、动效、语言和桌面行为。

主窗口不再提供右下角悬浮宠物入口。桌宠通过原生窗口、托盘和快捷面板进入主窗口，避免同一入口在多个位置重复出现。

## 3. 窗口与空间规则

### 紧凑桌宠

透明窗口只包含宠物、状态标签和必要的连接错误。默认逻辑尺寸为 180 × 180，宠物缩放只改变这一区域。

### 展开面板

快捷面板、事件、菜单和设置与宠物共享透明窗口，但在布局中占据独立网格区域。面板优先出现在宠物右侧，右侧空间不足时换到左侧。宠物锚点在展开和收起时保持稳定，窗口整体限制在当前显示器工作区。

面板尺寸集中于 `src/desktop/pet-layout.ts`，页面结构不得自行覆盖这些窗口尺寸。CSS 只负责内部布局，不通过绝对定位把面板叠在宠物上。

### 主窗口

打开主窗口前读取宠物、主窗口和当前工作区的物理尺寸。依次比较右侧、左侧、上方和下方候选位置，选择不重叠且修正距离最小的位置。若当前屏幕无法容纳任何完全不重叠的位置，选择重叠最小的方案，并保留原生窗口的移动能力。

### 窄窗口

应用导航在窄窗口中转为顶部水平导航。主内容使用单列，项目行先显示主要信息，再在较宽窗口中展开状态与箭头。任何输入、长标题和主机名都必须允许收缩或换行。

## 4. 视觉系统

### 令牌来源

- 设计源文件：`petdeck/tokens/petdeck.json`
- 运行时映射：`petdeck/src/styles/tokens.css`
- 应用组件：`petdeck/src/styles/app.css`
- 桌宠组件：`petdeck/src/styles/pet.css`

采用原始值、语义、组件三层结构。组件只消费语义变量或 Spark 映射变量，不在页面中新增独立色板。

### 色彩

暖白与中性灰承担主要表面，深紫用于主要操作和选中状态，杏色只保留为品牌细节。成功、等待、错误和信息色仅表达对应语义。深色主题重新平衡表面和文字，不直接反转浅色主题。

### 字体与层级

使用本机 Aptos、Segoe UI Variable 和中文系统字体，不引入联网字体依赖。页面主标题使用显示字体与紧凑字距，正文保持可读行高。会话正文限制在阅读宽度内，数字和用量使用等宽数字。

### 表面与圆角

普通项目使用分隔线和表面差，不给每个容器添加阴影。浮层使用完整细边框和有限的色染阴影。控件、卡片和浮层分别使用统一圆角，不在页面内随机增加新半径。

## 5. 组件与状态

所有交互元素必须具备：

- 默认、悬停、键盘焦点和按下状态。
- 可用时的禁用状态。
- 异步操作的处理中状态，并保留可理解的标签。
- 输入项的内联错误和修复建议。
- 可选项的选中状态，使用 `aria-pressed`、`aria-current` 或对应原生语义。

主要操作使用主色，破坏性操作使用错误色。删除、退出等破坏性意图必须在触发位置和确认位置保持一致。

不使用原生下拉框绘制关键外观。少量互斥选项使用按钮选项组，复杂目标选择使用具备完整键盘能力的 Listbox 或 Combobox。

### 生命周期提示与归属

会话只在进入运行、完成、卡住或等待拍板的状态转变时提示一次；持续运行不得按轮询重复通知。事件卡、系统通知、快捷面板和主面板必须一致展示 Agent 显示名、项目名、会话任务与状态文字。系统通知不展示会话正文或完整本地路径。

真实会话按工作目录或来源项目标识归组，远程主机是会话与项目身份的一部分。没有元数据时使用「未识别项目」，不得统一塞入虚构项目。事件中的会话标识必须直接用于线程定位，本地与远程会话不得因原始 ID 相同而串联。

SSE 历史回放可用于数据同步和接力追踪，但不得触发启动通知。免打扰下只有等待拍板可以打断，其余事件进入收件箱；同一事件 ID 不得重复发送系统通知。

## 6. 动效

产品反馈动画控制在 300ms 以内，不使用弹性过冲、环境脉冲或永久装饰动画。动画只表达进入、退出、选择或进度变化。系统开启减少动效时，移除位移动画并保留即时状态反馈。

宠物自身的帧动画属于角色表现，不受面板位移动画规则限制，但仍受用户的宠物动效设置控制。

## 7. 文案

使用短句和具体动词。错误提示说明发生了什么以及下一步如何处理。成功提示只描述已经确认发生的事实。演示控制必须标明模拟性质，不出现在真实链路的操作区。

## 8. 品牌资产

沿用项目原有应用 Logo，不重新设计品牌标识。统一源文件为：

- `petdeck/src-tauri/icons/icon.png`
- `petdeck/public/brand-mark.png`

界面与 favicon 直接复用同一份 PNG，原生图标目录保持既有发行资产。品牌更新是独立任务，不与界面主题调整混合。

## 9. 验收要求

每次界面变更至少执行：

```bash
npm run typecheck
npm test
npm run lint
npm run build
```

窗口几何需要覆盖右边缘、下边缘、负坐标、缩放和展开收起。浏览器走查需要覆盖浅色、深色、真实离线、演示数据、键盘焦点、窄窗口和完整接力流程。未能运行的渲染、真机或对比度检查必须明确标记为未验证，不得以构建通过代替体验验收。
