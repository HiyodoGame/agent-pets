## 1. 结论摘要

项目整体完成度比预期高：分层架构、纯逻辑抽离、测试密度（30 个测试文件 / 约 472 处断言 / 0 处 any）、安全实现（token/Origin/Host/限流）都达到了可以小步发布的水平，Phase 1-3 的加固计划确实落在了代码上。**「缺少很多内容」的感觉主要来自四个真实缺口**：竞品覆盖的 Agent 范围更宽（Cursor/Gemini CLI/OpenClaw 等都没有适配器）、成本/配额维度完全缺失、开源发行配套（LICENSE/CHANGELOG/安装包产物）为零、以及「接力」赛道正被一波新工具抢注而本产品尚无可分发的安装版本。

最优先的一件事与代码无关：**工作区有大量未提交改动（含全部 10 项审查修复与桌面化重构的最终态）**，任何调研结论都建立在这个不稳定基线上，应先落 commit。

## 2. 现状核实（代码层面，非文档自述）

### 2.1 架构与代码质量：良好，局部偏重

分层是清晰对称的：server 侧 `bridge.mjs`（HTTP+SSE 路由+安全，约 235 行）是唯一粘合层，纯逻辑下沉到 `freshness.mjs` / `tiers.mjs` / `bus.mjs`，适配器统一 `observe/inject` 接口，无 shell 的 spawn 与参数注入防护集中在 `adapters/exec.mjs`；前端侧 `data.tsx`（约 171 行）是唯一 Provider 粘合层，同步决策、连接状态机、轮询门、快照缓存、去重、追踪全部抽成可单测纯模块。全仓库 0 处 TODO/FIXME，`tsconfig` strict，src 非测试代码 0 处 `any`。

需要处理的问题（均已在代码中核实，非文档转述）：

| 问题 | 位置 | 说明 |
| --- | --- | --- |
| 前端事件总线是死代码 | `src/adapters/bus.ts` | 仅被 `index.ts` re-export，全 src 无消费者，与 server `bus.mjs` 平行但未接线 |
| 交接包文本双份手工镜像 | `server/tiers.mjs:19-25` ↔ `src/adapters/registry.ts:23-29` | 逐字重复，靠 parity 测试兜底，是脆弱的双维护点 |

### 2.2 一个此前未被记录的安全缺口

**GET 类端点（`/api/sessions`、`/api/events`、`/api/agents`，`bridge.mjs:148-157`）无 token 也无 Origin 校验** —— 本机任意进程可直接读会话标题与最后一条消息。token 只守 inject 写路径。这与隐私红线「会话内容本地优先」不冲突（数据确实没出机器），但与「别的本机进程也不该随便读我的会话」的预期不符，且竞品调研显示多机器/共享桌面场景是真实使用形态。建议按写路径同样的 Host+Origin+可选 token 方案补齐，改动面小。

### 2.3 测试与真实 CLI 验证的落差

30 个 JS/TS 测试文件（server 9 + src 21）约 472 处断言，Rust 另有 5 个 `#[test]`；bridge 安全、exec、freshness、observe 解析、前端全部纯逻辑模块覆盖较好。但：四个 flow 主组件零渲染测试（无 @testing-library/react）；`data.tsx` 的完整 effect 链仅靠纯函数间接覆盖；**无任何 E2E**；README:16 自己承认「真实 CLI 的兼容性尚未在所有适配器上逐一完成安装版实测」。fake 测试证明了逻辑正确，不能证明 codex/claude/opencode 真机可用——这是接力假设成立与否的最后一步，缺一张真机实测矩阵（OS × CLI 版本 × observe/inject × 结果记录）。

### 2.4 Rust 壳完整度

较高：单实例、托盘菜单、窗口隐藏而非退出、bridge 子进程崩溃重启（`bridge.rs:48-70`）、Node≥24 检测、随机 token + 动态端口、dev/release 双路径资源解析。缺：DND 与托盘勾选态不持久化（`lib.rs:91` 默认 false）、无命令日志落盘。

### 3.4 AI/Agent 设计对比结论

本项目的 observe（读本地 jsonl / opencode serve）+ inject（headless CLI argv/stdin，无 shell）+ 能力三级分级（full/observe-only/manual）+ 剪贴板降级，在工程实现上比同类桌宠扎实得多（竞品普遍仅观察）。接力内容打包（context/instruction/artifacts 统一 builder + attempt 关联 + unconfirmed 状态）也比 sctxx 之外的工具完整。**短板不在设计而在覆盖与交付**：4 个适配器里 1 个（kimi）仅观察，网页类 Agent 注入侧空缺（PRD 已知），以及没有任何已发布产物。

## 4. 功能缺口清单（按价值排序）

1. **Cursor 与 Gemini CLI 适配器** —— 竞品桌宠的标配覆盖，前端工程师群体渗透率最高的两个 Agent，目前完全没有。
2. **成本/配额维度** —— token 用量、限额倒计时、花费。竞品三家当核心功能做，本项目埋点体系在位、加一层展示即可起步。
3. **可分发安装版本** —— NSIS 包只在本地构建产物里，无 release 工作流、无签名、无自动更新。407★ 的 agentpet 已经双平台可装，这是传播差距的主因。
4. **开源基础配套** —— LICENSE 与 CHANGELOG 全仓库缺失；无面向最终用户的安装/故障排查手册（现有 README 是开发者向）。
5. **跨机器/远程会话**（SSH 或局域网 bridge 联邦）—— frieren 与 sitrep 验证了需求，属于差异化纵深。
6. **Flow3 面板深度** —— 对照 1185★ 竞品的看板与编排，当前只读+追问的面板是最容易被替代的模块；考虑看板视图或轻编排。
7. **宠物情感系统**（成长/喂养/皮肤商店）—— 桌宠品类的留存抓手，现仅 1 套 default 皮肤；skin-loader 架构已在位，扩起来成本低。
8. **i18n** —— 全部中文硬编码（含 Rust 托盘），竞品全是英文；出海零成本障碍。
9. 网页类 Agent 注入侧、全自动编排（方向 C）—— PRD 已明确延后，维持该决策。

## 6. 建议路线图

**P0（本周内，低成本高杠杆）**

1. 把工作区改动整理落成 commit 并推送（先跑全量质量门），这是其他一切的地基。
2. GET 端点补 Host+Origin+可选 token 校验（`bridge.mjs:148-157`），并把「读端点受保护与否」写进 README 安全说明。
3. 补 LICENSE（影响一切开源传播，5 分钟工作量）。
4. desktop.yml 补 `cargo fmt --check`；新增 release 工作流：tag 时产出 NSIS artifact 到 GitHub Release。

**P1（2-4 周，验证接力假设的窗口期）**

5. 真机实测矩阵：对 codex/claude/opencode/kimi 逐一记录 OS × CLI 版本 × observe/inject 结果，把 README:16 的免责变成事实清单。
6. Gemini CLI + Cursor 适配器（observe 优先，inject 量力）。
7. 成本/配额 MVP：先做 Claude 用量% + 重置倒计时（对标 petdash，数据源已知）。
8. CHANGELOG + 用户手册（安装/前置条件/故障排查）。

**P2（1-2 月，拉开差距）**

9. 跨机器会话（SSH observe 先行）。
10. 皮肤第二套 + 宠物成长系统（对标 agentpet 的留存抓手）。
11. Flow3 看板视图；DND 持久化；flow 拆分与死代码清理（bus.ts、双份交接包文本合一）。
12. 自动更新（Tauri updater）+ i18n。

**P3（视验证结果）**：网页 Agent 注入、方向 C 编排、macOS 移植。
