# M1 实施计划：运行时骨架 + Claude Code 纵向切片

> 状态：已实施，真实环境验收通过（Kimi Code + Tauri 桌面/桌宠，2026-11-20）
> 上游：《产品定义 v0》《交互与信息架构 v1》《架构与技术选型 v2》《M0 技术验证报告》

## 1. 目标与出口

M1 只做一件事：把「项目 → 任务 → Agent 进程 → 实时事件 → 停止/续接」这条链路在真实仓库上跑通。

出口（可验收）：

1. 登记一个本地 git 仓库，创建任务，点开始后 3 秒内任务详情出现实时事件。
2. Assistant 文本、工具调用、工具结果按到达顺序显示；完成后显示最终结果与耗时。
3. 停止能结束整棵进程树，任务状态变为「已停止」；续接能沿用同一 Claude 会话继续。
4. 桥接重启后，项目、任务、运行记录与事件流可恢复。
5. Agent 的改动只落在任务的 worktree，不污染主工作区。
6. 新增单测与桥接测试通过：pnpm typecheck、pnpm test。

## 2. 范围

### 做

- 运行时骨架：SQLite、事件总线、进程监督、适配器接口、worktree 服务。
- Claude Code 适配器：启动、流式事件、停止、续接、会话 ID。
- 控制台最小骨架：今日（任务列表）+ 任务整页（实时流、停止/续接）。
- 桌宠只显示「有任务在跑 / 完成」两态，不做决策。
- 旧只读观察接口保留，不动现有面板。

### 不做（留给 M2/M3）

- 经理模型、任务拆解、派发确认。
- 多 Agent 并行、排队、依赖、暂停（挂起进程）。
- 决策卡、验收/打回、产物预览、合并。
- 桌面端 Agent、Codex/Kimi/opencode 适配器。
- 成长/亲密度接入关键路径。

## 3. 技术方案

### 3.1 新增模块

~~~
petdeck/server/runtime/
  db.mjs            SQLite 打开、迁移、项目/任务/运行/事件读写
  event-bus.mjs     统一事件类型、持久化、SSE 订阅
  supervisor.mjs    子进程生命周期、stdout 行切分、退出、杀进程树
  worktree.mjs      git worktree 创建/移除、分支命名
  service.mjs       编排：建任务、开始、停止、续接、状态迁移
  adapters/claude-code.mjs  命令构造、stream-json 解析、事件映射
  adapters/registry.mjs     适配器注册与能力位
~~~

运行时只依赖 Node 内置模块；SQLite 用 node:sqlite；不引入新的原生依赖。

### 3.2 适配器接口

~~~js
// 能力位先按 Claude Code 的真实能力填，不假装
{
  id: 'claude-code',
  name: 'Claude Code',
  capabilities: {
    host: true,          // 可托管进程
    stream: true,        // 结构化事件流
    resume: true,        // 可按会话 ID 续接
    steer: false,        // M1 不支持运行中追加消息
    decisions: false,    // M1 不接权限请求
    pause: false,        // M1 不做进程挂起
  },
  buildStart({ prompt, cwd, permissionMode }) -> { command, args, env },
  buildResume({ prompt, cwd, sessionId, permissionMode }) -> { command, args, env },
  parseLine(line, ctx) -> NormalizedEvent[],
}
~~~

### 3.3 Claude Code 调用

首次启动：

~~~
claude -p --verbose --output-format stream-json --permission-mode <mode> <prompt>
~~~

续接：

~~~
claude -p --verbose --output-format stream-json --resume <sessionId> --permission-mode <mode> <prompt>
~~~

- 用参数数组启动，不经过 shell；prompt 作为独立 argv，做前导横线保护。
- 继承用户环境变量，只把 cwd 指到 worktree；不隔离 HOME/配置目录，复用登录。
- 权限模式：M1 默认 acceptEdits（允许改文件，命令按 Claude 默认策略），另提供「本轮自动执行」开关，对应 bypassPermissions，并在派发时明确提示。
- 停止：Windows 用 taskkill /PID <pid> /T /F；非 Windows 用进程组信号。
- 会话 ID 从 system/init 事件读取，写入 runs.session_id。

### 3.4 事件归一化

Claude stream-json 事件映射到统一类型：

| Claude 事件 | 统一事件 | 说明 |
|---|---|---|
| system/init | run.started | session_id、model、cwd、tools |
| assistant 文本块 | message.assistant | role=assistant，含文本 |
| assistant tool_use 块 | tool.started | 工具名、输入摘要、调用 ID |
| user tool_result 块 | tool.completed | 输出摘要、is_error、调用 ID |
| result | run.completed / run.failed | is_error、result、duration_ms、cost |
| stderr | log.stderr | 截断保留，标记来源 |
| 进程退出 | run.exited | exitCode、signal |

事件统一字段：id、runId、taskId、seq、type、ts、payload。所有事件追加写 runs/<runId>/events.jsonl，并同步写 DB 索引。

### 3.5 数据库

最小表：

- projects(id, name, path, kind, created_at)
- tasks(id, project_id, title, prompt, agent, status, worktree_path, branch, created_at, updated_at)
- runs(id, task_id, session_id, pid, status, started_at, ended_at, exit_code)
- events(id, run_id, seq, type, ts, payload_json)

任务状态：待开始 → 运行中 → 已完成 / 已失败 / 已停止。数据库路径：%APPDATA%/PetDeck/petdeck.sqlite（WAL）。

### 3.6 worktree

- 路径：%LOCALAPPDATA%/PetDeck/worktrees/<projectSlug>/<taskId>
- 分支：petdeck/<taskId>
- 创建：git -C <repo> worktree add -b <branch> <path> HEAD
- 移除：M1 只在任务删除时提示，不自动删，避免误删未提交改动。
- 非 git 项目：M1 不纳入托管，登记时标记为「仅观察」。

### 3.7 桥接 API

新增，全部走现有 token + Origin 校验：

- GET  /api/runtime/projects
- POST /api/runtime/projects           { path, name? }
- GET  /api/runtime/tasks
- POST /api/runtime/tasks              { projectId, title, prompt, permissionMode }
- GET  /api/runtime/tasks/:id
- POST /api/runtime/tasks/:id/start
- POST /api/runtime/tasks/:id/stop
- POST /api/runtime/tasks/:id/resume   { prompt? }
- GET  /api/runtime/tasks/:id/events   ?after=<seq>
- GET  /api/runtime/tasks/:id/stream   SSE

旧 /api/sessions、/api/events、/api/inject 保持原样。

### 3.8 界面

最小两页：

- 今日：左栏任务列表（状态、项目、更新时间），右栏空态/当前任务；顶部「新建任务」。
- 任务整页：顶部状态与操作（开始/停止/续接），左栏实时事件流，右栏元信息（项目、分支、worktree、会话 ID、耗时）。
- 入口：/today 设为默认；旧 /panel、/connect、/relay 保留在侧栏「旧版」分组。
- 组件沿用现有 Tailwind 与 i18n，不引入新 UI 库。

## 4. 三周拆解

### 第 1 周：骨架与适配器 spike

- 建 runtime 目录、SQLite 迁移、事件类型。
- Claude 适配器最小可跑：真实仓库里启动一次任务，stdout 落 JSONL。

- 产出：curl 能完成建任务 → 开始 → 看事件 → 停止 → 续接。

### 第 3 周：界面与验收

- 今日 + 任务整页；事件流自动滚动、工具卡折叠。
- 桌宠两态接入；错误与空态。
- 真实仓库端到端验收，修边角，更新文档。
- 产出：v0.2 可自用切片。

## 5. 测试与验收

自动化：

- claude-code 解析器：用录制的 stream-json 样本覆盖 init、assistant 文本、tool_use、tool_result、result 成功/失败。
- supervisor：注入假 spawn，验证行缓冲、退出码、停止时杀进程调用。
- worktree：临时 git 仓库，验证创建分支与路径、重复创建报错。
- 桥接：注入假 service，验证鉴权、参数校验、SSE 首包、事件 after 游标。

手工验收：

1. 在真实仓库登记项目，建任务「给 README 加一行说明」，开始。
2. 观察事件流依次出现 init、assistant、tool_use、tool_result、result。
3. 停止一个长任务，确认进程树消失、状态 stopped。
4. 续接同一任务，确认 Claude 记得上一轮内容。
5. 重启桥接，刷新页面，任务与事件仍在。
6. 检查主工作区 git status 无新改动，改动只在 worktree。

- **运行时客户端字段名不一致**：`runtime-client.ts` 发 `project_id`/`permission_mode`，桥接读 `projectId`/`permissionMode`，导致建任务 500（`Provided value cannot be bound to SQLite parameter 1.`）。已统一为 camelCase，并新增 `runtime-client.test.ts` 2 条契约测试。
