## 1. 目标与出口

M3 把 M2 的「任务完成」从一次运行结束，扩展成一条可审查、可打回、可合并的完整生命周期。

出口（可验收）：

1. 任务结束不再直接算完成，而是进入「待验收」；用户能看到本轮总结与产物。
2. 产物自动登记，图片可在页面内查看，视频/音频可按 Range 拖动，PDF/文本可下载。
3. 通过验收后：git 项目进入「待合并」，非 git 项目直接完成。
4. 打回必须填写意见，可指定接手 Agent；打回后回到待开始，可选择续接原会话或换 Agent 重跑。
5. 合并需要二次授权：验收通过只代表「可以合并」，确认合并前还必须生成一次性 token。
6. 主仓库不干净、目标分支不对、合并冲突都会被拒绝，并返回可读原因；绝不强推。
7. 合并成功后可选清理 worktree 与分支；已合并任务仍保留会话、产物和验收记录。
8. 刷新页面或换窗口后，未合并任务可重新生成授权，旧 token 立即失效。
9. typecheck、单测、桥接测试通过。

## 3. 状态与数据模型

### 3.1 任务状态

| 状态 | 含义 | 谁进入 |
| --- | --- | --- |
| ready | 待开始 | 新建、打回、清理后重跑 |
| queued | 排队中（等并行槽位） | 开始/续接时已满员 |
| running | 运行中 | 进程已启动 |
| waiting | 待决策 | 最终回复被识别为提问 |
| paused | 已暂停 | 用户暂停，进程挂起，仍占槽位 |
| review | 待验收 | 子进程退出且无待决策 |
| pending_merge | 待合并 | git 项目验收通过 |
| merged | 已合并 | 带 token 合并成功 |
| completed | 已完成 | 非 git 项目验收通过、放弃合并、或无需合并 |
| failed | 失败 | 启动失败、非零退出、Agent 报错 |
| stopped | 已停止 | 用户停止或桥接重启结算 |

关键顺序：**review 只在子进程退出后出现**。`run.completed` 先写结果与 summary、收集产物，等 `run.exited` 落 exit_code 后再请求验收，避免「进程还在跑就先验收」。

### 3.2 SQLite v3

- projects 新增 `base_branch`（登记时记录当前分支，合并目标以它为准）。
- tasks 新增 `summary`、`last_feedback`、`reviewed_at`、`merged_at`、`merge_token`、`merge_token_expires`、`reject_count`。
- artifacts：id、task_id、run_id、name、kind、mime、bytes、stored_path、source、created_at；按 task 建索引。
- 迁移仍用 `PRAGMA user_version`，v2 库自动补列、建 artifacts，升到 3；不重建表。
- 对外序列化：`publicArtifact` 去掉 stored_path；`decorateTask` 去掉 merge_token，只暴露 `merge_token_expires`。

## 4. 产物

### 4.1 自动收集

- 扫描本轮事件里 `tool.started` 的 `path/file_path/filePath/notebook_path/notebookPath`。
- 跳过只读类工具：read / ls / glob / grep / search / list / web / fetch。
- 再扫 worktree 的 `git status --porcelain`，把图片/视频/音频/PDF 等媒体扩展名补进来。
- 按 `name:bytes` 去重，单次最多 30 个，单文件上限 50MB。
- 文件复制到 `<data>/artifacts/<taskId>/<random16hex>-<basename>`，任务与 worktree 被清理后产物仍在。

### 4.2 预览与下载

`GET/HEAD /api/runtime/artifacts/:id/content`：

- 支持 `?token=`（与桥接 token 同一把）与 Bearer/Header。
- 单段 Range：`206` + `Content-Range` + `Accept-Ranges: bytes`；越界 `416`。
- image/video/audio/pdf 用 `inline`，其余 `attachment`。
- 前端图片用 `<img>`，视频/音频用原生控件，PDF/文件走新窗口或下载。

## 5. 验收、打回、合并与清理

### 5.1 验收

- 仅 `review` 可验收。
- git 项目：`pending_merge`，生成 32 位十六进制 token，10 分钟过期，返回 `merge_required=true`。
- 非 git 项目：直接 `completed`，写 `reviewed_at`，不出现合并。
- 决策超时也会把任务推进到 `review`，并记 `decision.expired`；不自动选择。

### 5.2 打回

- 仅 `review` / `pending_merge` 可打回；意见必填，长度 ≤ 4000。
- 同一 Agent 且已有会话：用 `--resume` 续接，保留上下文。
- 换 Agent：清空 session，prompt 拼「原始要求 + 上轮总结 + 打回意见」。
- 写 `last_feedback`、`reject_count+1`、`reviewed_at=null`、`merge_token=null`，状态回 `ready`。
- 容量不足时排队，槽位释放后按原 Agent 与 prompt 重跑。

### 5.3 合并授权

`POST /tasks/:id/authorize-merge`：

- 仅 `pending_merge`，否则 `409 TASK_NOT_PENDING_MERGE`。
- 生成新 token，旧 token 立即失效；用于「验收后关了页面/换了窗口」的场景。
- 前端把 token 只存在内存里，刷新后必须重新授权。

### 5.4 合并

`POST /tasks/:id/merge {token}`：

- `timingSafeEqual` 校验 token；过期 `MERGE_TOKEN_EXPIRED`，错误 `MERGE_TOKEN_INVALID`。
- 主仓库 dirty：`MERGE_DIRTY`，返回文件列表。
- 当前分支不是 base：`MERGE_WRONG_BRANCH`。
- `git merge-tree` 预检冲突：`MERGE_CONFLICT`，返回冲突文件。
- 实际执行 `git merge --no-ff <branch> -m 'PetDeck: merge <title>'`。
- 成功写 `merged_at`、清 token、记 `task.merged`；不 push、不删分支。

### 5.5 放弃与清理

- `abandon-merge`：`pending_merge → completed`，清 token，记 `task.merge_abandoned`。
- `cleanup`：允许 `merged/completed/stopped`；`git worktree remove --force` + `git branch -D`，清空 worktree_path/branch，记 `task.cleaned`。
- 清理失败返回 `CLEANUP_FAILED`，不假装成功。

## 6. API 与界面

### 6.1 新增 API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/runtime/artifacts/:id/content | GET/HEAD，支持 Range 与 token |
| DELETE | /api/runtime/artifacts/:id | body `{taskId}` |
| POST | /api/runtime/tasks/:id/accept | 通过验收，返回 merge token |
| POST | /api/runtime/tasks/:id/reject | body `{feedback, agent}` |
| GET | /api/runtime/tasks/:id/merge-preview | 分支、提交、diff、冲突预检 |
| POST | /api/runtime/tasks/:id/authorize-merge | 重新生成合并授权 |
| POST | /api/runtime/tasks/:id/merge | body `{token}` |
| POST | /api/runtime/tasks/:id/abandon-merge | 放弃合并 |
| POST | /api/runtime/tasks/:id/cleanup | 清理 worktree 与分支 |
| GET/POST | /api/runtime/tasks/:id/artifacts | 列表 / 手动登记 |

### 6.2 控制台

- 任务页 `review`：顶部验收面板 = 本轮总结 + 产物画廊 + 通过验收 + 打回；打开展示打回意见与接手 Agent。
- 任务页 `pending_merge`：合并面板 = 分支/目标分支/提交数/diff/冲突预检 + 生成授权 + 确认合并 + 放弃。
- 任务页右栏：产物列表（图标、大小、删除、手动登记相对路径）。
- 今日页：7 项统计（运行/排队/需处理/待验收/待合并/暂停/完成）；「需处理」只算待决策与失败，不重复统计验收/合并。
- 任务板：9 列（待开始、排队、运行、待拍板、已暂停、待验收、待合并、需处理、已完成）。
- 已结束任务：今日页只保留「打开任务」，不再显示禁用的「重试」。
- 桌宠：本次未改；M2 的决策入口继续可用。

## 8. 已知缺口

- **已补齐（2026-11-21）**：真实 Agent 的「完成→验收→打回→重跑」用 opencode 2.0.30（`opencode-go/deepseek-v4.1-flash`）真机跑通，一次 49.45s 走完 review→reject→rerun→accept→authorize-merge→merge→cleanup，run2 续接同一 `ses_` 会话并收到完整打回意见（新建 `second.txt` 后主仓库 hello/second 均在）。可复跑：`cd petdeck && npm run test:e2e:opencode`（`petdeck/scripts/opencode-e2e.mjs`，自建临时仓库与数据目录，约 1 分钟，需本机已登录 opencode）。
  - 这轮真机验收暴露并修掉了三个此前只有单测覆盖不到的缺陷：① Windows 上 npm 的 `.cmd` shim 经 `cmd.exe /c` 托管时，命令行在第一个 LF 处被截断，多行提示词（打回意见）只剩第一行 —— 改为解析 shim 目标直接 spawn 真二进制，并对仍走 cmd 的路径把换行折成空格；② opencode 后台守护进程把自己的 cwd 设成 worktree，Windows 下目录被占用，`git worktree remove` 报 `Permission denied` —— 运行改用 `--standalone`（私有 server，跑完不留守护进程）；③ merge 后 worktree 注册已摘除但目录残留时，cleanup 直接 409 —— 改为 `disposeWorktree`：短暂重试后确认「已不在注册表」才删残留目录 + `worktree prune`，仍注册才报错。
  - 仍未走真实验收：Claude Code（cc-switch 网关 502）、Codex（托管适配器未接）。
- 合并面板与产物预览在 Tauri 窗口内未单独手工复测；本次走查在 Chrome + Vite 下完成，复用同一套前端。

## 9. 验收步骤

1. 登记一个 git 仓库，新建任务并运行到结束：任务进入待验收，右栏出现产物。
2. 打开产物图片/视频：图片显示、视频可拖动，Range 返回 206。
3. 填写打回意见并指定另一 Agent：任务回待开始，旧会话不被覆盖，新运行带原始要求 + 总结 + 意见。
4. 重新跑完并通过验收：git 项目变待合并；非 git 项目直接完成。
5. 刷新页面再合并：必须先「生成合并授权」；旧 token 不可用。
6. 制造冲突后合并：返回 `MERGE_CONFLICT` 与冲突文件，主分支不变。
7. 合并成功：主分支出现改动；清理 worktree 后分支与目录消失，任务仍可打开。
8. 今日页统计不重复；任务板九列均可访问。
9. typecheck、单测、oxlint、build 全绿。
