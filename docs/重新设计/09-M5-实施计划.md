## 1. 目标与出口

M4 结束时，「一句话 → 提案 → 确认派发 → 验收/打回/合并 → 日报」已经能跑通，但离 v1 还差三件事：看不见（出问题只有一句离线横幅）、留不住（没有文件日志、崩溃后靠猜）、发不稳（安装依赖外部 Node、更新入口简陋）。M5 把这三件事补齐，并用「连续自用一周」作为最终验收。

出口（可验收）：

1. **可观察**：设置页有「运行状态」卡（bridge 版本、Node、端口、数据目录、日志目录、各 Agent 版本探测），托盘显示运行状态并可重启本地服务；一键导出脱敏诊断包。
2. **崩溃恢复**：bridge 被杀或崩溃后重启，任务与运行记录如实标记中断（bridge-restarted），界面给出「继续（同一会话）」入口；DB 损坏时自动备份重建；残留 worktree 自动清理。
3. **日志留存**：bridge 与运行时写文件日志（按天 + 大小轮转，默认保留 7 天）；bridge 起不来时 sidecar 日志仍能记录原因（Node 缺失、端口占用、脚本错误）。
4. **更新流程**：已安装的 0.1.3 能经真实 GitHub Releases 更新到 0.2.0，发现 → 下载（显示进度）→ 验签 → 安装 → 重启全通；失败按网络/签名/磁盘分类提示；发布清单文档化。
5. **性能**：1000 与 5000 事件的任务页可交互（首屏 P95 < 1s），事件内存有上限、可向上翻页回放；长列表滚动不掉帧。
6. **可访问性**：键盘可完成「新建 → 运行 → 验收 → 合并 → 清理」全流程；模态与抽屉有焦点陷阱与 Escape；运行状态变化有 aria-live；对比度与 reduced-motion 达标；检查表逐项勾选。
7. **Cursor 转录接入**：今日页「观察中的会话」只读呈现 Cursor 等 observe-only 来源的最近转录；任务板、验收、合并不混入观察会话。
8. **内置 Node**：安装包内置 Node 24 sidecar，PATH 中没有 Node 的干净 Windows 也能首启（消除 03 §12 第 1 条的前置依赖与 ROADMAP P0 的未勾选项）。
9. **文档**：用户手册重写覆盖新控制台与故障排查；真机实测矩阵回填；npm run docs:check 全绿。
10. **发布**：v1.0-rc 打包发布（先发 0.2.0 作为更新链路与自用周基线），随后连续自用 7 天无阻断问题 → 发正式 v1.0。

### W2. 崩溃恢复（2 天）

现状：db.recoverInterrupted()（petdeck/server/runtime/db.mjs:425-430）在启动时把 starting/running/paused 的 run 置 failed + error='bridge-restarted'，任务置 stopped，queued 回 ready；task.session_id 保留，resumeTask（petdeck/server/runtime/service.mjs:1161）可同会话续跑，前端任务页/今日页已有 canResume 分支。缺的是：中断原因不显眼、崩溃现场不留证据、DB 损坏无兜底、队列中断后无人管。

要做：
- 中断横幅：任务页与今日页显示「上次运行因本地服务重启中断（run <id>，<时间>）」+「继续（同一会话）」+「放弃」；续跑复用既有 resume，不新造接口。
- 崩溃现场：bridge 启动时若发现 dataDir/crash-*.json 未消费则提示；运行时未捕获异常写 crash-<ts>.json（node 版本、参数摘要、最后 50 行日志、活跃任务 id）。
- DB 完整性：启动时 PRAGMA integrity_check（quick_check 足够快），失败则把库备份为 petdeck.db.bak-<ts> 并新建空库，事件与提示写日志，UI 显示「本地数据已备份重建」。
- 队列恢复：queued 回 ready 后按并发上限自动调度（已有 scheduleDrain，补一条启动即 drain 的测试），避免重启后队列永久卡住。
- 残留清理：启动时对每个任务执行 disposeWorktree 的残留判断（isWorktreeRegistered），把「已摘注册只剩目录」的情况清掉并记事件。

验收：真机 opencode 任务在运行中 taskkill bridge → 重启后任务显示中断原因、可续跑并跑完；暂停中 kill 同样可续；队列中断后重启自动派发；人为截断 db 文件后启动自动备份重建且应用可用。

### W7. 安装包内置 Node 24 sidecar（2 天）

现状：petdeck/src-tauri/src/bridge.rs:126-138 只查 PATH 上的 node，版本不够或缺失就整页提示安装；安装包不含运行时（bundle.externalBin 未配置）；ROADMAP P0 的「干净 Windows 首启」因此一直未勾。

要做：
- 构建期获取：petdeck/scripts/fetch-node.mjs 下载官方 node-v24.x-win-x64.zip（记录 sha256 与版本到 node-runtime.json），解出 node.exe 放到 petdeck/src-tauri/binaries/node-x86_64-pc-windows-msvc.exe（该目录 gitignore，不入库二进制），并把 LICENSE 一并拷进 resources。
- tauri.conf.json：bundle.externalBin: ["binaries/node"]；beforeBuildCommand 先跑 fetch-node（已有缓存则跳过）。
- bridge.rs：解析顺序 = resource 目录内置 node → PATH node（开发态）→ 报错；版本判断对内置 node 也生效；错误文案区分「内置运行时缺失（安装损坏，建议重装）」与「系统 Node 版本过低」。
- CI：petdeck 的 desktop.yml / release.yml 在 Windows runner 执行 fetch-node（带缓存），构建产物验证内置 node 存在。
- 体积：记录 0.2.0 与 rc 的安装包/安装后大小，在 README 与 CHANGELOG 说明。

**体积与许可底线（2026-11-21 定）**：
- 许可：只分发**官方未修改**的 Node.js Windows x64 二进制（MIT），不自行编译、不打 patch；随包附 `nodejs/LICENSE` 与 `nodejs/THIRD_PARTY_LICENSES`（含 OpenSSL Apache-2.0、libuv MIT、V8 BSD、zlib 等）全文，放 `resources/third-party/nodejs/`；「关于」/设置页显示内置 Node 版本与许可入口。
- 体积：本机实测 `node.exe` v24.18.0 **88.2 MB**（gzip -9 后 33.8 MB，NSIS LZMA 通常更小）。目标：安装包增量 ≤ **40 MB**，安装后总占用 ≤ **110 MB**；若某版本压缩后超过 40 MB，先评估改用「首启按需下载 + 校验」，不再直接塞包。验收时把实际数字写进 README 与 CHANGELOG。
- 供应链：CI 下载官方 zip 并按官方 `SHASUMS256.txt` 校验 SHA256（发布物同时校验）；版本号钉在 `scripts/fetch-node.mjs` 的常量与 `node-runtime.json`，升级需单独提交并记录 hash。

验收：在 PATH 中移除 Node（或在只有旧版 Node 的虚拟机）安装 NSIS 后首启正常、能启动 bridge 并跑任务；移除安装目录里的内置 node.exe 后提示「安装损坏」而非「请安装 Node」；CI 绿色且产物含 node.exe。
