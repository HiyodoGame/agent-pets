# PetDeck 重新设计 · 产品定义 v0

> 状态：待确认 · 2026-11-20
> 范围：只定义「成品是什么」，不含排期与技术方案。确认后进入交互/架构设计，再排开发计划。
> 依据：2026-11-20 三轮需求访谈（本会话）。

## 0. 一句话

PetDeck 是给 OPC（一人公司）开发者的**本地 Agent 调度台**：把项目里的开发任务派给不同 Agent 并行执行，用你自己的模型服务做拆解、汇总与汇报；**桌宠常驻桌面负责「一眼看见、随手决策」，控制台负责「详细运行、复杂操作」**。

## 1. 用户与问题

- **用户**：独立开发者 / 一人公司，同时维护多个项目，机器上装了多个 Agent。
- **分工**：Agent 做开发；人做审查、测试、上架、验收。
- **现状痛点**：
  - Agent 一多，不知道谁在跑、跑到哪、卡在哪、要不要拍板；
  - 每个 Agent 一个终端/窗口，切换成本高；
  - 跨项目没有总览，任务分派靠脑子记；
  - 完成后要挨个翻记录才知道做了什么。
- **产品承诺**：打开一个地方，知道全部项目与 Agent 的现在；派活、盯进度、拍板、验收都在这里完成。

## 2. 核心概念

| 概念 | 定义 |
| --- | --- |
| 项目 | 一个 git 仓库（代码项目）或工作目录（视频/设计等非代码项目）；可关联产物目录 |
| 任务 | 可验收的工作单元：标题、目标（给 Agent 的指令）、验收标准、指定 Agent、依赖（可选）、状态、worktree/分支、产物、运行记录 |
| 运行 | 任务的一次执行；一个任务可以多次运行（打回重做） |
| Agent | 统一抽象的执行者；能力分级见 §5 |
| 经理模型 | 只做拆解与汇报，不执行、不直接派发 |
| 产物 | 视频、截图、文件、diff 等 |
| 验收 | 通过 / 打回（意见回到指定 Agent，开新运行） |

**任务状态机**：

待确认 → 排队 → 运行中 ⇄ 已暂停 → 等你决策 → 待验收 → 通过 → 待合并 → 已合并（仅 git 项目）

打回：回到排队；旁支：失败、已中止。

## 3. 核心循环

| # | 谁 | 发生什么 |
| --- | --- | --- |
| 1 | 你 | 打开控制台 → 今日视图：项目、运行中、待确认、待验收 |
| 2 | 你 | 选项目，对经理说目标；或直接在任务板建任务 |
| 3 | 经理 | 拆成任务草案：目标、验收标准、建议 Agent、依赖 |
| 4 | 你 | 确认或修改；**确认前不派发** |
| 5 | 软件 | 为 git 项目建 worktree，启动 Agent，任务进入运行 |
| 6 | 软件 + Agent | 采集输出与状态；Agent 自述阶段总结；桌宠播报；需要选择时弹窗 |
| 7 | 你 | 桌宠上直接选；或在控制台补话、暂停、中止 |
| 8 | Agent | 完成 → 软件归集一句总结 + 产物预览（视频/截图） |
| 9 | 你 | 验收：通过（git 项目进入待合并，授权后合并），或打回并指定 Agent（开新运行） |
| 10 | 经理 | 实时逐条 + 阶段总结 + 日报；控制台可查详情 |

## 4. 两个界面

### 4.1 桌宠（常驻、一眼看见、随手决策）

- **必须一眼看见**：当前有哪些项目、哪些 Agent 会话在运行、运行状态、进度、待决策数、完成/失败。
- **必须能直接做**：弹窗选项直接选；点条目进控制台对应位置；超时未选标出来并给控制台入口。
- **播报**：经理/Agent 的阶段总结与完成提示；要聚合、克制，不逐条刷屏。
- **入口**：单击展开摘要，进入控制台。
- 暂停/中止/补一句话：v0 只在控制台做（见 §11 假设 5）。

### 4.2 控制台（详细运行、复杂操作）

信息架构（v0）：

1. **今日**：经理对话入口 + 待确认 / 运行中 / 待验收 / 今日完成。
2. **项目**：项目列表、项目详情（任务板 + 会话/产物）。
3. **任务**：列表 / 看板；任务详情（运行输出、对话、产物、验收、运行历史）。
4. **Agent**：各 Agent 配置、可用性检测、并发上限。
5. **汇报**：实时事件流、阶段总结、日报。
6. **设置**：经理模型、项目目录、通知、外观、语言。

任务详情必须支持：发消息改需求、暂停/继续、中止重开、验收/打回。

## 5. Agent 接入

**能力模型**（按实测标注，不假装都支持）：

| 能力 | CLI Agent | 桌面 Agent（v0 目标） |
| --- | --- | --- |
| 启动 | 进程 + PTY | 启动 App / 激活窗口 |
| 观察 | stdout / 结构化事件 | 本地日志、会话文件或 API（逐个验证） |
| 发消息 | stdin | 多数不可；降级为复制指令手动粘贴 |
| 中止 | 杀进程树 | 关闭/停止（有限） |
| 暂停/继续 | 挂起进程树（Windows 需验证） | 不支持 |

**v0 名单**：

| Agent | 形态 | v0 能力 |
| --- | --- | --- |
| Codex | CLI | 托管（启动/观察/发消息/中止） |
| Claude Code | CLI | 同上 |
| opencode | CLI | 同上 |
| Kimi Code | CLI | 同上 |
| minimax design | 桌面/网页 | 启动 + 可观察（待验证） |
| Kimi | 桌面 | 启动 + 可观察（待验证） |

## 6. 任务与并行

- 同一项目的并行任务：**每个任务独立 worktree + 分支**（仅 git 项目）；软件创建与清理，**合并需你授权**，授权后由软件执行，冲突时停下交回人工。
- 非代码项目（视频/设计）不建 worktree，用独立工作目录或产物命名空间隔离。
- 任务依赖：手动配置；v0 不做自动触发。
- 审查是**独立任务**（由你或经理建议创建），v0 不做自动流水线。
- 并发上限按 Agent 可配（默认值 TBD）。

## 7. 经理模型

- **输入**：项目元数据、任务列表与状态、运行事件、Agent 自述总结、产物清单。
- **输出**：结构化任务草案（目标/验收标准/建议 Agent/依赖）、阶段总结、日报、问答。
- **硬约束**：不执行命令、不改仓库、不直接派发；派发前必须人工确认。
- **接入**：OpenAI 兼容 API / 本地模型 / 订阅账号（通过对应 CLI）。
  订阅账号的程序化使用有条款与稳定性风险，设置里要标注。

## 8. 汇报

- **事件**：状态变化、需决策、完成/失败 —— 实时。
- **阶段总结**：Agent 自述 → 软件归集 → 桌宠播报 + 控制台留档。
- **日报**：当天各项目/任务产出、阻塞、下一步建议，由经理生成。
- v0 不含 token/成本统计（TBD）。

## 9. 范围

**v0 做**：Windows 单机；项目 = git 仓库或工作目录（视频/设计等非代码项目同样纳入）；对话/手动建任务；人工确认派发；CLI 托管 + 桌面观察；git 项目的 worktree 隔离；产物预览（视频/截图）；桌宠播报与决策；日报。

**v0 不做**：云端与多人协作；自动合并/部署/上架；GUI 自动化点击；移动端、macOS、鸿蒙（后续）；完整 IDE / 代码编辑器；替你测试与发布。

## 10. 验收剧本（毛爪卡册）

1. 早上打开控制台：3 个项目，2 个在跑，1 个等你拍板。
2. 对经理说：「今天做卡册素材 20 张，再让 Claude 审一下昨天的代码。」
3. 经理拆出 2 个任务，建议 Codex / Claude；你确认。
4. 两个 worktree 启动，桌宠显示两条运行。
5. Claude 弹窗问「是否接受重构建议」，你在桌宠上直接选「接受」。
6. Codex 完成，桌宠播报一句总结；控制台看视频/截图预览。
7. 验收通过；Claude 任务打回，意见带回 Claude 重做。
8. 晚上经理出日报：两个项目各完成什么、卡在哪、明天建议。

## 11. 待确认的假设

1. 桌面 Agent 的可观察性要逐个验证；读不到就降级为「启动器 + 手动状态/产物变化推断」。
2. 预览 = Agent 产物（视频/截图），v0 不托管「运行项目」，测试仍由你手动。
3. worktree 由软件创建与清理；合并需你授权，授权后由软件执行。
4. 审查是独立任务，不做自动流水线。
5. 桌宠只做「看见 + 选择 + 跳转」；暂停/中止/补话在控制台。
6. v0 不做用量/成本统计。
7. 名称沿用 PetDeck，桌宠形象保留。
8. 发布节奏：先自用稳定，再公开给 OPC 开发者。

## 12. 与现有实现的关系

**复用**：Tauri 壳、桌宠窗口、托盘、通知、i18n、自动更新、设置存储；bridge 的 token/Origin 安全模型与 SSE；会话观察适配器（作为外部会话来源与桌面 Agent 观察）。

**重写/新增**：bridge 从「只读观察 + 注入」升级为「Agent 运行时宿主 + 任务调度」；新增项目/任务/运行数据模型、worktree 管理、进程托管（PTY）、经理服务、产物库、决策收件箱、日报；控制台 IA 以「今日/项目/任务」为主，不再以「会话列表」为主。

**降级**：现有「接力」从核心功能变为辅助能力（本质是给 Agent 发消息）；观察外部会话成为补充来源。
