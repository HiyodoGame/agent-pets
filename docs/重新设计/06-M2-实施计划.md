# M2 实施计划：多 Agent、调度与决策闭环

> 状态：已实施（2026-11-20），控制台真实数据游览与 API 验证通过；Tauri/桌宠决策回答待手工复测
> 上游：《产品定义 v0》《交互与信息架构 v1》《架构与技术选型 v2》《M0 技术验证报告》《M1 实施计划》
> 范围校正：经理模型、任务拆解、阶段总结属于 M4；M2 只做多 Agent 托管、调度、暂停/继续/中止与决策闭环，并为 M4 预留接口。

---

## 1. 目标与出口

M2 把「一次只能盯一个任务」变成「同时托管多个 Agent，并在它们需要人拍板时接住」。

出口（可验收）：

1. Claude Code、Kimi Code、opencode 三个 CLI 都能作为托管 Agent 启动任务；能力矩阵在 Agent 页可见，Codex 标「待代理」。
2. 同时启动的任务数受并行上限约束；超出的任务进入「排队中」，槽位释放后自动开始。
3. 任务可声明依赖；依赖未完成时不能开始，依赖完成后自动进入调度。
4. 运行中的任务可暂停、继续、停止；暂停保留进程与槽位。
5. Agent 在最终回复里提出问题并给出选项时，任务进入「待决策」，今日页与桌宠都能看到并回答；回答写回同一会话继续执行。
6. 决策超时只标记过期，绝不自动选择；过期后仍可人工回答。
7. 桥接重启后 queued 恢复为 ready、paused/running 结算为 stopped，不出现幽灵运行。
8. typecheck、单测、桥接测试通过。

## 2. 范围

### 做

- 运行时：SQLite v2（依赖、优先级、决策、设置）、调度器、暂停/继续、决策检测与回答。
- 适配器：新增 opencode 托管适配器；三个 CLI 统一能力位与创建任务接口。
- 桥接：agents、settings、decisions 接口，任务 pause/continue。
- 控制台：任务板 7 列、任务页决策卡与暂停/继续、今日页待决策入口、Agent 能力矩阵、新任务依赖/优先级、设置页调度项。
- 桌宠：待决策区、选项直接回答、新决策提示音（可关）、决策优先置顶。

### 不做（留给 M3/M4）

- 经理模型、任务拆解、派发确认、阶段总结、日报。
- 验收/打回、产物预览、git 合并。
- 桌面端 Agent（Cursor、Claude Desktop 等）。
- Codex 托管（需网络代理）、多机/SSH。
- 暂停时冻结子工具进程的强一致保证（见风险）。

## 3. 状态与数据模型

### 3.1 任务状态

| 状态 | 含义 | 谁进入 |
| --- | --- | --- |
| ready | 待开始 | 新建、桥接重启后的 queued、停止/失败后可重试 |
| queued | 排队中（等并行槽位） | 开始任务时已满员 |
| running | 运行中 | 进程已启动 |
| waiting | 待决策 | 最终回复被识别为提问 |
| paused | 已暂停 | 用户暂停，进程被挂起，仍占槽位 |
| completed | 已完成 | 进程成功结束且无待决策 |
| failed | 失败 | 启动失败、非零退出、Agent 报错 |
| stopped | 已停止 | 用户停止或桥接重启结算 |

### 3.2 SQLite v2

- tasks 新增 `depends_on TEXT DEFAULT '[]'`、`priority INTEGER DEFAULT 0`、`queued_prompt TEXT`、`queued_resume INTEGER DEFAULT 0`。
- decisions：id、task_id、run_id、question、options_json、allow_freeform、status(pending/answered/expired)、answer、created_at、answered_at、expires_at。
- settings：key、value_json。默认 `maxConcurrent=2`、`decisionTimeoutMinutes=30`、`decisionSound=true`、`decisionAlwaysOnTop=true`。
- 迁移用 `PRAGMA user_version`：v1 库补列、建 decisions/settings，再升到 2。

## 4. 调度与生命周期

### 4.1 开始

1. 校验依赖：所有 depends_on 任务必须 completed，否则 409 `DEPENDENCY_NOT_MET`。
2. 若 `active.size >= maxConcurrent`：任务置 queued，记 `task.queued`，返回 202。
3. 否则正常启动：创建 run、worktree、进程，置 running。

### 4.2 槽位释放

进程退出（完成/失败/停止）后从 active 移除，调用 drainQueue：按 priority 降序、created_at 升序挑选 queued 任务，依赖满足则启动；依赖不满足保持 queued。暂停不释放槽位。

### 4.3 暂停 / 继续

- 暂停：仅 running 且 active 有句柄；Windows 用 PowerShell + Add-Type 调 `NtSuspendProcess`（含递归子进程）；run/task 置 paused，记 `run.paused`。
- 继续：仅 paused 且句柄仍在；`NtResumeProcess`，恢复 running，记 `run.resumed`。
- 非 Windows 或调用失败返回 `PAUSE_UNAVAILABLE`（501），不假装成功。
- 停止：先 resume 再杀进程树，保证被挂起的进程树也能结束。

### 4.4 决策

- 仅在 run.completed 时识别；文本取 result 或该 run 最后一条 assistant 消息。
- 检测器只认「有提问意图 + 至少两个可选项」或「明确要求确认/选择」；纯问号不弹卡，避免误报。
- 命中且任务有 session：创建 decision，任务置 waiting，记 `decision.requested`。
- 回答：写 decision.answered，记 `decision.answered`；把「用户选择：…」作为续接 prompt 排队/启动同一会话。
- 超时：读接口懒结算为 expired，记 `decision.expired`；不自动选择、不结束任务。
- 无 session 的任务不做决策检测（无法写回，避免假闭环）。

## 5. Agent 适配器与能力矩阵

| Agent | 托管 | 流式 | 续接 | 权限模式 | 备注 |
| --- | --- | --- | --- | --- | --- |
| Claude Code | 是 | stream-json | --resume | default/acceptEdits/bypassPermissions/plan | 网关 502 时真实运行受阻 |
| Kimi Code | 是 | stream-json | -S session | default | 已真实跑通 |

| Codex | 否 | app-server | resume | — | 需要网络代理，标「待代理」 |

适配器新增能力位：`capabilities.host/stream/resume/freeform/suspend` 与 `permissionModes`；Agent 页据此渲染矩阵，不硬编码。

## 6. HTTP 接口

- `GET /api/runtime/agents`：适配器与能力、可用状态。
- `GET/PUT /api/runtime/settings`：调度与决策设置。
- `GET /api/runtime/decisions?status=open`：待决策/已过期。
- `POST /api/runtime/decisions/:id/answer`：`{answer, optionIndex}`。
- `POST /api/runtime/tasks/:id/pause`、`/continue`。
- 任务详情增加 decisions、queue 信息。

## 8. 风险与限制

| 风险 | 处理 |
| --- | --- |
| 挂起父进程时子工具进程可能仍在收尾 | 递归挂起进程树；文档标注非强一致 |
| 决策检测误报/漏报 | 只认显式选项；结果可忽略/继续；不自动选择 |
| 多任务同时写同一仓库 | 每任务独立 worktree；非 git 项目串行建议写进提示 |
| opencode 输出格式变化 | 适配器单测锁定事件形状；未知行降级 log.stdout |
| 并行上限设太大导致机器卡顿 | 默认 2，设置页可调 1–8 |

## 9. 验收步骤

1. 设置并行上限 1，连续开始两个任务：第二个 queued；第一个完成后第二个自动 running。
2. 建 B 依赖 A：A 未完成时开始 B 返回依赖错误；A 完成后 B 可开始。
3. 运行长任务，暂停：进程挂起、状态 paused、槽位仍占用；继续后事件恢复。
4. 让 Agent 在最终回复给出两个选项：任务 waiting，今日与桌宠都出现决策；点选项后同一会话继续。
5. 决策超时：状态 expired，任务仍 waiting，可人工回答。
6. 桥接重启：queued→ready、running/paused→stopped。
7. Agent 页能力矩阵、设置页四项设置可读写。
8. typecheck、单测、桥接 e2e 全绿。
