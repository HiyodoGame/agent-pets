# 交互与信息架构 v1

> 状态：已确认（2026-11-20）；实现细节以 v2 为准
> 依据：《产品定义 v0》（已确认，含合并授权、非代码项目纳入、不做成本统计的修订）
> 能力依据：2026-11-20 对 4 个 CLI 与已安装桌面端的实查（§5）
> 本版回答三件事：界面长什么样、任务怎么流转、每个 Agent 能接多深。

---

## 1. 原则修订

旧规范（docs/设计与交互规范.md）的第一原则是「宠物优先」：桌宠是常驻主体，面板是临时的。
新定义改为：**控制台为主，桌宠是常驻状态层。**

保留：
- 轻、暖、快，不打扰；动效 < 300ms。
- 有后果的动作必须确认。
- 不假装完成：没验证的不报成功。

新增四条：
1. **一屏看清**：谁在干、干到哪、卡在哪，任何页面都能回答。
2. **决策带上下文**：弹出来的时候必须带项目、Agent、问题、选项后果，否则就是在逼人瞎选。
3. **三个有后果的动作必须显式确认**：派发、合并、打回。
4. **失败与超时永远可见**：不自动重试、不自动跳过、不安静地消失。
5. **可追溯**：每个任务的完整会话、决策、产物、合并记录都能回看。

## 2. 控制台

窗口最小 1280×800。左侧固定导航 6 项：今日 / 项目 / 任务 / Agent / 汇报 / 设置。

### 2.1 今日（默认页）

今日 = 经理对话 + 需要你处理。左侧对话是主输入，右侧是待办流。

~~~
┌────────────┬───────────────────────────┬──────────────────────────┐
│  PetDeck   │  经理对话                  │  需要你处理               │
│            │                           │                          │
│ ● 今日     │  [你] 把毛爪卡册的开屏改成 │  ▲ 待确认 2               │
│ ○ 项目  7  │       暗色，周末前要能看   │  ┌────────────────────┐  │
│ ○ 任务 12  │                           │  │ 拆成 3 个任务？     │  │
│ ○ Agent  4 │  [经理] 我拆成 3 个任务：  │  │ 开屏暗色 / 素材替换 │  │
│ ○ 汇报     │        1. 改主题令牌       │  │ / 动效调整          │  │
│ ○ 设置     │        2. 重做开屏         │  │ [确认派发] [调整]   │  │
│            │        3. 替换 20 张素材   │  └────────────────────┘  │
│            │        确认后派发。        │                          │
│            │  [确认] [调整] [放弃]      │  ● 运行中 3              │
│            │                           │  毛爪卡册·Codex·素材加载  │
│            │                           │  ██████░░ 62%  12m      │
│            │                           │  官网改版·Claude·落地页   │
│            │  ┌─────────────────────┐  │  ███░░░░░ 31%  6m       │
│            │  │ 说点什么…            │  │  ...                    │
│            │  └─────────────────────┘  │                          │
│            │                           │  ○ 待验收 1  ◇ 完成 4    │
└────────────┴───────────────────────────┴──────────────────────────┘
~~~

- 对话：经理只做拆解与汇报；消息可以带项目、任务、产物引用（点开跳转）。
- 待确认：经理拆的任务卡、Agent 抛上来的决策、待合并的授权请求，都在这里排队。
- 运行中：项目 · Agent · 任务 · 进度 · 已用时，点进任务详情。
- 待验收 / 今日完成：可折叠，避免刷屏。

### 2.2 项目

- 列表按状态分组：进行中 / 已归档；行内显示仓库类型（git / 工作目录）、运行数、待处理数、最近活动。
- 详情页：
  - 左：项目简介、路径、默认 Agent、关联的产物目录。
  - 右：任务列表（与任务板同源，按状态分组）。
  - 顶部：新建任务 / 对经理说 / 打开目录。
- 非代码项目（视频、设计）用同一个模型，只是没有分支与合并。

### 2.3 任务

- 看板列：待确认 / 排队 / 运行中 / 等你决策 / 待验收 / 待合并 / 完成。
- 卡片：项目 chip、Agent chip、进度条、已用时、决策角标；悬停显示最新一条阶段总结。
- 点卡片进入**任务整页**（返回时保留看板筛选与滚动位置）：
  - 顶部：状态、项目、Agent、进度、已用时、操作（暂停 / 中止 / 补话）。
  - 左主栏：**实时会话流**——Agent 的完整输出（消息、工具调用、命令、diff、错误），逐条流入；可搜索、按类型过滤、折叠长内容；默认跟随最新，向上滚动即暂停跟随。
  - 右栏：任务说明、worktree/分支、依赖、时间线、产物（视频/截图内嵌预览、打开文件夹）。
  - 底部：输入框，直接补话或改需求。
  - 完成后：会话流保留，上方切到验收区（一句总结 + 产物 + 通过 / 打回；打回写意见并选接手 Agent）。
- 待合并任务显示分支、变更摘要、[授权合并]；冲突时停在这里，给出冲突文件与入口。

### 2.4 Agent

- 两个页签：命令行 / 桌面端。
- 每个 Agent 一张卡：名称、可执行路径、版本、能力标签（启动 / 观察 / 发消息 / 暂停 / 中止）、[测试] 按钮、默认模型与参数。
- 未安装显示「未安装」，给出探测到的期望路径。
- 能力标签不是许愿：绿=已验证，黄=部分可用，灰=降级为启动器。

### 2.5 汇报

- 按天分组的时间线；每条包含项目、任务、阶段总结、产物缩略图。
- 过滤器：项目 / Agent / 日期。
- 一天结束时经理生成一份「今日汇报」，可在这里回看。

### 2.6 设置

- 模型：经理模型（OpenAI 兼容 / 本地 / 订阅账号）+ 每个 Agent 的模型覆盖；测试连通。
- 调度：最大并行数、worktree 根目录、产物目录约定、默认超时。
- 桌宠：尺寸、位置、显示模式、提示音。
- 通知：弹窗、声音、免打扰时段。
- 通用：语言、主题、开机自启、更新。

## 3. 桌宠

保持 180×180 的常驻形象。收起时只显示状态徽标，点击展开状态面板。

~~~
╭──────────────╮
│              │
│    ◕‿◕       │
│              │
│   ●2  ▲1     │
╰──────────────╯
~~~

展开（360 宽，锚定在宠物旁）：

~~~
╭─ 运行中 2 ─────────────────────────╮
│ 毛爪卡册 · Codex · 素材加载   62%  │
│   阶段：已替换 12/20 张            │
│ 官网改版 · Claude · 落地页    31%  │
│   阶段：正在写首屏文案             │
│ …还有 1 个                         │
├────────────────────────────────────┤
│ ⚠ 等你决定 1                       │
│ 官网改版 · Claude                  │
│ 「用 A 方案还是 B 方案？」         │
│ [A] [B] [详情]        剩余 4:32    │
├────────────────────────────────────┤
│ 今日完成 4 · 查看汇报 →            │
│ [打开控制台]                       │
╰────────────────────────────────────╯
~~~

规则：
- 运行中最多 3 行，多出的折成「还有 N 个」，不无限长高。
- 决策选项 ≤3 且短时直接内联；否则只显示「详情」跳任务。
- 阶段总结以气泡形式出现 5 秒；多条排队，不叠加。
- 超时：倒计时结束变红「已超时 N 分钟」，**播放提示音并把桌宠置顶**，仍然留着，**永不自动选**。
- 完成：轻提示「毛爪卡册 · Codex 完成」，点开进验收。
- 桌宠不做破坏性操作：暂停、中止、合并、打回一律在控制台。
- 点击展开，失焦或 Esc 收起；不抢焦点。

## 4. 任务状态机（细化）

~~~
待确认 ──确认──> 排队 ──启动──> 运行中 ⇄ 已暂停
                                    │
                          需要你决定 ┘（运行中不退出，等回答）
                                    │
                                    ▼
                                 待验收 ──打回──> 排队
                                    │
                                    ├─通过（非代码）──> 完成
                                    └─通过（git）──> 待合并 ──授权──> 已合并
                                    │
                                    └─失败 / 已中止
~~~

| 状态 | 进入方式 | 可做 | 超时/异常 |
|---|---|---|---|
| 待确认 | 经理拆解、手动新建 | 确认派发 / 调整 / 放弃 | 不超时，一直等 |
| 排队 | 确认后、打回后 | 取消 | 并行上限满时排队 |
| 运行中 | 进程启动成功 | 补话、暂停、中止、看日志 | 超过阈值标黄提醒 |
| 已暂停 | 人工暂停 | 继续、中止 | — |
| 等你决策 | Agent 提出问题 | 选一个 / 自己回答 / 中止 | 超时标红，不处理 |
| 待验收 | Agent 自述完成 | 通过 / 打回 | 不超时 |
| 待合并 | 通过且是 git 项目 | 授权合并 / 放弃合并 | 冲突则停住 |
| 已合并 | 合并成功 | 归档 | — |
| 完成 | 非代码项目通过 | 归档 | — |
| 失败 / 已中止 | 进程异常退出 / 人工中止 | 重跑、改后重跑 | 保留日志 |

规则：
- 同一任务多次运行保留历史（第 N 次），卡片默认显示最新一次。
- 打回必须写意见 + 选 Agent，生成新的运行，不覆盖旧的。
- 合并是唯一会改主分支的动作，必须逐次授权；冲突不自动解决。
- 非代码项目没有 worktree 与合并，通过即完成。

## 5. Agent 适配矩阵

三种接入深度，UI 上用能力标签表达：

- **托管型**：能建会话、读事件、发消息、收产物 → 一等公民。
- **观察型**：能读到会话与状态，但不能可靠地发消息 → 显示 + 派发时给替代路径。
- **启动器型**：读不到 → 只负责启动，状态靠人工或产物推断，界面必须如实标注。

### 5.1 命令行（已实查，2026-11-20）

| Agent | 会话/消息接口 | 观察 | 暂停 | 中止 |
|---|---|---|---|---|
| Codex | exec；app-server；queue --thread --message | app-server 事件 / ~/.codex 记录（待验证细节） | 待验证 | kill |
| Claude Code | -p；--bg + attach/logs；--resume | 后台会话输入输出 + ~/.claude/projects | 待验证 | claude stop / kill |
| Kimi Code | -p；stream-json；acp；session list | stream-json + ~/.kimi | 待验证 | kill |
| opencode | run；serve；api session.list | serve SSE / 日志（本机 --help 因沙箱 EPERM 未跑通，需复测） | 待验证 | kill |

注：暂停/继续先试 Windows 进程树挂起；若对某个 CLI 不安全，降级为「停止 + 用会话 id 续跑」。

### 5.2 桌面端（已安装）

| Agent | 可执行 | 观察 | 发消息 | 中止 |
|---|---|---|---|---|
| Cursor | E:\AI\cursor\Cursor.exe | ~/.cursor/projects 转录（已有适配器） | 无 | 关闭窗口 |
| Kimi 桌面 | C:\Users\Con_WKK\AppData\Local\Programs\kimi-desktop\Kimi.exe | Roaming\kimi-desktop 为 Electron 数据，非结构化，待验证 | 无 | 关闭窗口 |
| MiniMax Design | E:\Others\MiniMax Design\MiniMax Design.exe | 未找到数据目录，待查 | 无 | 关闭窗口 |
| Claude Desktop | 未安装 | 待安装后探测 | 无 | 关闭窗口 |

桌面端统一按「启动器 + 手动状态」设计，读到就升级，读不到不假装。

### 5.3 统一接入策略

1. 优先各家原生协议：codex app-server / claude --bg + attach / kimi ACP / opencode serve。
2. 运行中发消息优先 queue / resume，不模拟键盘。
3. PTY + stdin 只作兜底，不用于解析状态。
4. 每个 Agent 适配器都声明能力位；调度器只看能力位，不做特判。
5. 读不到就降级并在界面上标注，禁止把「未知」显示成「正常」。

## 6. 五个关键流程

**A 派发**
你在对话里提需求 → 经理拆成任务卡（含 Agent 建议、依赖）→ 你确认 → 建 worktree → 启动 → 进入运行中。

**B 决策**
Agent 提出选择 → 变成决策卡（问题、选项、后果、所属任务）→ 桌宠与今日同时出现 → 你在任意一处选 → 写回 Agent 会话 → 继续运行。超时只提醒，不代选。

**C 验收**
运行完成 → 一句总结 + 产物 → 你通过：git 项目进待合并，授权后合并；非代码项目直接完成。

**D 打回**
写意见 + 选接手 Agent → 新运行，旧记录保留 → 回到排队。

**E 日报**
一天结束 → 经理按项目汇总阶段总结与产物 → 汇报页可回看。

## 7. 概念数据模型（草案）

- Project：id、name、path、kind（git / 工作目录）、defaultAgent、managerThread、artifactDir
- Task：id、projectId、title、brief、agentId、status、dependencies[]、runIds[]
- Run：id、taskId、attempt、sessionRef（各家协议句柄）、worktree/branch、startedAt、endedAt、status、lastEventAt
- Decision：id、runId、question、options[]、status（pending/answered/timeout）、answer
- Artifact：id、runId、kind（video/image/file/link）、path、preview
- Report：id、scope（project/day）、period、text、runIds[]
- AgentConfig：id、kind（cli/desktop）、exePath、protocol、capabilities、model、params

## 8. 可行性红线（开发前必须逐个验证）

1. **运行中发消息**：codex queue 已确认存在；claude / kimi / opencode 需实测。做不到就用「停止-补话-续跑」，但体验要如实说明。
2. **暂停/继续**：Windows 进程挂起对 4 个 CLI 是否安全；不安全就退化为「停止 + resume」。
3. **决策识别**：能否拿到结构化的「等待用户选择」事件；拿不到则用输出文本 + 规则/模型判断，必须允许你手动纠正误判。
4. **桌面端可观察性**：Kimi 桌面、MiniMax Design 数据在哪、能否读到；读不到就按启动器处理。
5. **订阅账号程序化调用**：是否可行、是否违反条款。
6. **重启恢复**：应用重启后能否重连正在跑的会话（app-server 常驻、claude bg 是否可重连）。

## 9. 已确认（2026-11-20）

1. 控制台默认页 = 今日（对话 + 待办），项目/任务作为下钻。
2. 桌宠 180×180，展开 360 宽面板，运行中最多显示 3 行。
3. 任务详情为**整页**，实时监控 Agent 会话的全部内容。
4. 决策超时：不自动选、保持待处理；**加提示音并置顶**。
5. 非代码项目「通过即完成、没有合并」。
6. 验收与决策**逐个确认**，v0 不做批量。
