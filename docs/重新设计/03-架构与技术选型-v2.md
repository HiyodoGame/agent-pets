> 状态：草案，待确认
> 依据：《产品定义 v0》《交互与信息架构 v1》（均已确认）
> 目标：在现有仓库上演进到「托管 + 调度」架构，给出可执行的里程碑与验证点。

---

## 1. 架构总览

保留现有外壳（Tauri 2 + WebView2 + React 19 + Node bridge），把 bridge 从「只读观察 + 注入」升级为「本地运行时」。

~~~
┌────────────────────── PetDeck 桌面（Tauri 2 + WebView2）──────────────────────┐
│  主窗口：控制台（React 19 + TS + Tailwind）      桌宠窗口：/pet（透明、置顶）  │
│        │  HTTP + SSE 127.0.0.1:5199（token 鉴权）          │                   │
└────────┼──────────────────────────────────────────────────┼───────────────────┘
         ▼                                                  ▼
┌──────────────────── 本地运行时（Node 24 sidecar，server/）────────────────────┐
│  网关(HTTP/SSE)   事件总线   调度器   进程监督   产物服务   经理(LLM)         │
│  ──────────────────────────────────────────────────────────────────────────  │
│  Agent 适配层：codex / claude / kimi / opencode / cursor / launch-only        │
│  SQLite(node:sqlite) + runs/<id>/events.jsonl + artifacts/<task>/             │
└──────────────────────────────────────────────────────────────────────────────┘
~~~

- 桌面端只做展示与交互，所有状态与副作用在运行时里；关掉主窗口，任务继续跑。
- 桌宠是同一套 SSE 的另一个订阅者，不单独维护状态。
- 不做远程：仍然只绑 127.0.0.1，token 由 Tauri 启动时生成并注入 WebView。

## 2. 运行时设计

### 2.1 核心模块

| 模块 | 职责 |
|---|---|
| 网关 | REST（项目/任务/运行/决策/产物/设置）+ SSE 事件流；沿用现有鉴权与 Origin 校验 |
| 事件总线 | 内存发布订阅 + 每运行一份 events.jsonl；断线重连用 Last-Event-ID 续传 |
| 调度器 | 队列、最大并行数、任务依赖、worktree 创建与清理、合并执行 |
| 进程监督 | 启动/停止/暂停/继续 Agent 进程树；孤儿进程清理；崩溃归类 |
| 产物服务 | 登记产物、生成缩略图（可选）、按 Range 提供视频流 |
| 经理 | 只做拆解与汇报；通过工具创建「待确认」提案，没有直接派发工具 |

### 2.2 统一事件

所有适配器输出归一化成同一组事件，UI 不认某个 Agent 的私有格式：

- session.started / session.exited / session.idle
- message.delta / message.done（角色：assistant / user / system）
- tool.call / tool.result（名称、入参摘要、结果摘要）
- command.output（stdout/stderr 行）
- decision.requested（问题、选项、是否阻塞）
- artifact.created（路径、类型、来源）
- error（分类：spawn / protocol / auth / timeout / exit）

事件同时写 events.jsonl，任务整页的「实时会话流」就是它；重开页面可回放。

### 2.3 进程管理要点

- 每个运行对应一个进程树，记录根 PID 与启动时间；退出时记录退出码。
- 停止：先温和中断，超时后整树强杀；保证不留孤儿。
- 暂停/继续：优先用 Windows 进程挂起（NtSuspendProcess / NtResumeProcess）；对某个 CLI 不安全时，降级为「停止，之后用会话 id 续跑」，并在 UI 上写清楚。
- 重启恢复：启动时扫描未结束的运行，能重连的（如常驻 app-server / 后台会话）重连，不能的标为「已失联」，给重跑入口。

### 2.4 worktree 与合并

- 仅 git 项目：git worktree add ../<root>/<task>-<id> -b petdeck/<task>-<id>。
- 分支命名固定前缀，便于清理与识别。
- 合并：只在「待合并 + 授权」后执行；先做冲突检测，冲突则停住并列出文件。
- 清理：任务完成或放弃后删除 worktree 与分支（保留可选）。

## 3. Agent 适配层

### 3.1 接口

每个适配器实现同一组能力位，运行时只按能力位调度：

~~~ts
interface AgentAdapter {
  id: string;
  probe(): Promise<{ installed: boolean; path?: string; version?: string; auth?: string }>;
  capabilities: {
    launch: boolean; observe: boolean; send: boolean;
    pause: boolean; resume: boolean; stop: boolean; artifacts: boolean;
  };
  start(req: { cwd: string; prompt: string; model?: string; sessionId?: string }): Promise<SessionHandle>;
  send(h: SessionHandle, text: string): Promise<void>;
  pause(h: SessionHandle): Promise<void>;
  resume(h: SessionHandle): Promise<void>;
  stop(h: SessionHandle): Promise<void>;
  subscribe(h: SessionHandle, emit: (e: NormalizedEvent) => void): () => void;
}
~~~

能力位在探测时写入数据库，UI 用绿/黄/灰三档展示；探测失败就降级，不假装。

### 3.2 四个 CLI 的接入策略

| Agent | 首选协议 | 备选 | 关键待验证 |
|---|---|---|---|
| Codex | app-server（JSON-RPC over stdio） | exec --json + queue | app-server 起会话/事件 schema/queue 写回 |
| Claude Code | -p --verbose --output-format stream-json + --resume | --bg + logs/attach | 运行中发消息、权限请求结构 |
| Kimi Code | -p --output-format stream-json + -S | acp（stdio） | 会话续接、事件完整性 |
| opencode | serve + SSE | run + 日志 | serve API 与事件、鉴权 |

桌面端（Cursor / Kimi / MiniMax Design / Claude Desktop）走「启动器适配器」：能读转录的读（Cursor），读不到就只有启动与人工状态，能力位如实为灰。

### 3.3 决策识别

优先拿结构化事件；拿不到时用输出文本 + 规则（问号、选项列表、等待输入提示），必要时用小模型判定。
判定结果永远可被你手动纠正；运行时绝不自动替你选。

## 4. 数据与文件

- 数据库：%APPDATA%/PetDeck/petdeck.sqlite（WAL）；用 Node 24 内置 node:sqlite，不引入原生模块。
- 转录：%APPDATA%/PetDeck/runs/<runId>/events.jsonl（追加写，DB 只存指针与摘要）。
- 产物：默认 %APPDATA%/PetDeck/artifacts/<taskId>/，也支持任务里指定的项目内目录。
- worktree：%LOCALAPPDATA%/PetDeck/worktrees/<projectSlug>/<task>-<id>，不放在项目仓库里。
- 设置：%APPDATA%/PetDeck/config.json；密钥后续用 Windows DPAPI 加密（M4/M5）。
- 迁移：DB 版本号 + 顺序迁移脚本，启动时自动执行。

主要表：projects、tasks、runs、decisions、artifacts、reports、agents、settings、migrations。
（runs 存 sessionRef、pid、worktree、分支、状态、时间；decisions 存问题、选项、答案、超时时间。）

## 5. 经理（LLM）

- 提供商：OpenAI 兼容（自定义 baseURL/模型/密钥）、本地（Ollama/LM Studio 同协议）、订阅 CLI（实验，用 claude -p / codex exec 当后端）。
- 工具集（刻意最小）：
  - propose_tasks：把一句话拆成任务卡（标题、说明、建议 Agent、依赖），只生成「待确认」。
  - revise_proposal：按你的意见改提案。
  - summarize_run：读运行摘要与产物，写阶段总结。
  - draft_daily_report：按项目汇总当天。
  - ask_user：需要澄清时提问。
- 没有 dispatch / merge / stop 工具。派发、合并、中止只能由你在界面上确认后调用运行时。
- 上下文只喂摘要与索引，完整转录按需读取，避免烧 token。

## 6. 前端结构

- 路由：/today、/projects、/projects/:id、/tasks、/tasks/:id、/agents、/reports、/settings、/pet。
- 状态：一个 SSE 订阅器 + 轻量 store（useSyncExternalStore），不引入重型数据层。
- 任务整页：左栏会话流（虚拟滚动、按类型过滤、搜索、跟随开关），右栏元信息与产物，底部输入；完成后切验收区。
- 桌宠窗口：复用现有 180×180 透明窗口；展开时 Tauri 调整窗口尺寸到 360 宽，收起还原；决策超时置顶并播放提示音。
- 通知：Tauri notification 插件 + 内置短音频；免打扰时段只在设置里关声音，不吞事件。
- 国际化：沿用现有 i18n 基础设施，新文案同步补齐。

## 7. 安全边界

- 只监听 127.0.0.1，token 每次启动生成；WebView 通过 Tauri 命令拿配置。
- 文件服务只暴露登记过的 run/artifact 路径，做路径规范化与越界检查。
- 可执行文件白名单：适配器注册表里的路径；任务 cwd 必须是已登记项目。
- Agent 可以 commit，不允许 push / 改主分支；合并必须带一次性确认令牌。
- 日志脱敏沿用现有纪律：只记录结构化错误码，不落提示词正文。

## 8. 技术选型

| 领域 | 选择 | 理由 | 风险 |
|---|---|---|---|
| 外壳 | Tauri 2（沿用） | 已有窗口、托盘、更新、单实例 | 无 |
| UI | React 19 + TS + Tailwind 4 + Router 7（沿用） | 现有栈 | 无 |
| 运行时 | Node 24 sidecar（沿用） | 适配器、子进程、流处理都在这里 | 用户机器需要 Node |
| 数据库 | node:sqlite（内置） | 零原生依赖、打包简单 | API 仍标实验 |
| 进程挂起 | koffi 调 Windows API | 一个库解决挂起/继续 | FFI 打包需验证 |
| PTY 兜底 | node-pty（按需） | 只有无协议 CLI 才用 | 原生模块编译 |
| 经理 | 原生 fetch 调 OpenAI 兼容 | 无 SDK 负担 | 各家兼容差异 |
| 视频预览 | HTML5 video + Range | 不转码、不装 ffmpeg | 编码兼容性 |
| 测试 | node --test（沿用） | 现有习惯 | UI 测试偏弱 |

关于 Node：现在安装包要求用户自己装 Node 24（src-tauri/src/bridge.rs 里检测）。产品化建议内置 node.exe 作为 sidecar，安装包大约多 80MB，但去掉前置条件。这条需要你拍板（§12）。

## 9. 迁移策略

保留：
- Tauri 外壳、双窗口、托盘、更新、单实例、窗口状态。
- 设计令牌与样式体系、i18n、构建与测试脚本。
- bridge 的鉴权/Origin 校验/结构化错误日志纪律。
- 现有日志解析器（codex/claude/cursor 等）作为「观察源」复用。

改造：
- 数据模型：会话中心 → 项目/任务/运行中心。
- 接力注入（tiers.mjs）→ 进程监督的 send()。
- 导航与页面：4 项 → 6 项；新增任务整页、Agent 页、汇报页。
- 桌宠：从主界面降为状态层，增加决策卡与置顶提醒。

归档：
- SSH 远程（真实 sshd 验证）移出主线，代码保留在开关后。
- 「接力」概念下线，能力并入运行中补话。
- 成长/亲密度：保留但移出关键路径（待你定，见 §12）。

## 10. 里程碑

按 1 人 + AI 协作估算，单位：全职当量周。

### M0 技术验证（2 周）
- 逐个跑通：codex app-server、claude --bg、kimi stream-json/ACP、opencode serve。
- 验证：运行中发消息、进程挂起/继续、决策识别、重启重连。
- 产出：能力报告 + 4 个最小适配器 demo + koffi/守护进程结论。
- 出口：每个 Agent 至少「起 → 看 → 发 → 停」跑通；暂停结论明确。

### M1 运行时骨架 + Claude Code 纵向切片（3 周）
- SQLite、事件总线、进程监督、适配器接口、worktree 服务。
- 控制台骨架：今日、项目、任务列表、任务整页（实时流）。
- Claude Code 适配器完整接入；桌宠显示运行状态。
- 出口：在真实项目上给 Claude Code 派一个任务，从确认到完成全流程可用（v0.2 可自用）。
- 变更（2026-11-20）：Codex 需要网络代理，暂缓；首个切片改为 Claude Code。详见《05-M1-实施计划》。

### M2 多 Agent + 决策闭环（3 周）
- Claude / Kimi / opencode 接入；能力矩阵在 UI 展示。
- 调度队列、并行上限、依赖；暂停/继续/中止。
- 决策卡：识别、桌宠与今日双入口、提示音与置顶、写回会话。
- 出口：4 个 CLI 都能被托管；决策可从桌宠回答。

### M3 验收、产物、合并（4 周）
> 状态：已实施（2026-11-21），详见《07-M3-实施计划》。
- 产物登记与预览（图片/视频，Range 流）；任务完成态。
- 验收/打回（意见 + 接手 Agent → 新运行）。
- 合并授权、冲突处理、worktree 清理。
- 出口：完整生命周期含合并；打回能正确重跑。

### M4 经理 + 汇报 + 设置（3 周，可与 M2/M3 并行）
- 经理客户端、拆解提案、阶段总结、日报。
- 设置页：模型、调度、桌宠、通知、密钥。
- 首次启动引导；i18n 补齐。
- 出口：一句话 → 提案 → 确认派发可用。

### M5 桌面端 + 打磨 + 发布（3 周）
- 桌面端启动器与可观察项；Cursor 转录接入。
- 崩溃恢复、日志留存、更新流程、性能与可访问性。
- 用户手册重写；安装包内置 Node（若拍板）。
- 出口：连续自用一周无阻断问题，发 v1.0-rc。

关键路径：M0 → M1 → M2 → M3（约 12 周）；M4 并行；总日历约 16 周。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| CLI 协议未公开/会变 | 适配器失效 | 版本探测 + 能力降级 + 适配器自带契约测试 |
| 进程挂起不安全 | 暂停不可用 | 降级停止+续跑，UI 如实标注 |
| 决策误判 | 打扰或漏掉 | 结构化优先；可手动纠正；绝不自动选 |
| 订阅账号条款 | 无法程序化 | API 优先；CLI 后端标实验 |
| 合并冲突 | 阻塞交付 | 冲突即停，列文件，人工处理 |
| 长会话吃内存 | 页面卡顿 | 事件落盘 + 虚拟滚动 + 分页回放 |
| Node 前置依赖 | 安装门槛 | 内置 node.exe sidecar |
| Tauri 打包 FFI/原生模块 | 构建失败 | M0 先验证 koffi；必要时改 Rust 守护进程 |

---

## 12. 已决策（2026-11-20，按推荐）

1. Node 运行时：安装包内置 node.exe sidecar，去掉「用户自装 Node 24」的前置条件。
2. 暂停实现：先试 koffi FFI 调 Windows API；打包或稳定性不过关再改 Rust 守护进程。
3. 经理后端默认 OpenAI 兼容 API；订阅 CLI 作为实验开关。
4. 成长/亲密度：保留，但移出关键路径。
5. 旧能力：保留只读观察（供桌面端使用与回放），删除接力注入。
6. 首个纵向切片：Claude Code（原定 Codex，因需要网络代理暂缓）。
7. Agent 权限：允许 commit，禁止 push 与直接改主分支；合并必须显式授权。
