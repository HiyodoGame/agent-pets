# PetDeck 宠物素材完整规格（供 Codex 生成使用）

> **历史设计简报（2026-11-16）。** 本文记录蓝噗重做时的要求及对旧绿色 `default` 的替换前审计；蓝噗现已成为 `default`。当前运行时规范以[皮肤模板](pet-skin-template.md)和实现代码为准，不与本简报并行维护。

版本：2.0　日期：2026-11-16
依据：[皮肤模板](pet-skin-template.md)（1.0）、`src/flows/shared/pet/skin-loader.ts`、`src/flows/shared/pet/skin-types.ts`、`src/flows/flow-1-pet-surface/pet-behavior.ts`，以及对当时 `default` 皮肤的逐帧审计。

## 0. 替换前素材的问题（为什么要重做）

对当时的 `default` 皮肤的 12 个代表帧做了审计，主要问题如下：

- 耳朵是独立浮在头顶的两个三角，与身体之间没有连接，看起来像贴纸而不是角色的一部分。
- 身体是圆球加小短腿，轮廓简单，缩到 96 px 后几乎只剩一个绿色圆点，与其他同类皮肤没有辨识度。
- 各状态差异主要靠小道具（笔记本、对勾、感叹号、爱心），角色本身的姿态变化很小，`work`、`think`、`attention` 之间不容易区分。
- `sleep` 与 `offline` 的身体被压成扁椭圆，轮廓与站立状态完全不同，切换时像换了一只宠物。
- 风格偏“贴纸图标”，线条粗细、阴影和配色都比较随意，没有统一的设计语言。

重做时请避免以上问题，尤其是耳朵与身体必须是一体轮廓。

## 1. 交付目录

```text
public/pets/<skin-id>/
├── manifest.json
├── preview.png            (256×256，代表性站立帧)
└── animations/
    ├── idle/0001.png … 0008.png
    ├── walk/0001.png … 0008.png
    ├── sleep/0001.png … 0006.png
    ├── drag/0001.png … 0002.png
    ├── drop/0001.png … 0006.png
    ├── pet/0001.png … 0006.png
    ├── work/0001.png … 0008.png
    ├── think/0001.png … 0006.png
    ├── done/0001.png … 0008.png
    ├── attention/0001.png … 0006.png
    └── offline/0001.png
```

同时需要更新 `public/pets/index.json` 的 `skins` 数组，把新 id 加进去。`skin-id` 只能使用小写英文字母、数字和连字符，例如 `mint-pip`。

## 2. 画布与锚点（硬约束，代码会校验）

| 项目 | 要求 |
| --- | --- |
| 画布 | 每一帧 256×256 px，RGBA 透明背景 PNG（允许无损 WebP，同一套动作只能用一种扩展名） |
| 默认朝向 | 朝右。应用会水平镜像得到朝左，因此角色不能有只在右侧出现的文字或不对称签名道具 |
| 锚点 | `x=128, y=224`。普通站立帧的脚底中心落在 y=224 |
| 安全区 | 常规角色包围盒位于 `x=28..228, y=24..224` 内 |
| 禁止项 | 背景色块、地面、白底、阴影贴片、水印、文字、边框；不允许按包围盒自动裁剪画布 |

manifest 中 `frameSize` 必须是 256×256，`anchor` 必须是 `{x:128,y:224}`，`direction` 必须是 `"right"`，否则加载失败。

## 3. 动作表与代码中的触发关系

| action | 帧数 | fps | 播放 | 触发场景（来自 `pet-behavior.ts`） | 内容要求 |
| --- | ---: | ---: | --- | --- | --- |
| `idle` | 8 | 8 | loop | Agent 空闲；done/stuck 结束后的常态 | 轻微呼吸，偶尔眨眼；首尾自然衔接 |
| `walk` | 8 | 12 | loop | 随机漫步 | 原地踏步，左右脚交替；位移由应用控制 |
| `sleep` | 6 | 6 | loop | 长时间无操作 | 闭眼趴伏、缓慢呼吸；**身体高度与站立时的比例要接近，不要压成扁饼** |
| `drag` | 2 | 8 | loop | 用户拖拽 | 被提起，四肢离开基线，表情可爱不痛苦 |
| `drop` | 6 | 12 | once | 拖拽结束落地 | 下落、落地、轻微回弹，末帧回到稳定站立 |
| `pet` | 6 | 12 | once | 用户戳/摸 | 开心回应，可加少量爱心或腮红，不可遮住脸 |
| `work` | 8 | 12 | loop | Agent 运行中（running） | 专注工作，小幅爪子或道具动作，不要大幅蹦跳 |
| `think` | 6 | 10 | loop | Agent 思考中（thinking） | 眼神上移、轻点下巴，动作克制 |
| `done` | 8 | 12 | once | 任务完成（done） | 短时庆祝，最后回到稳定姿势 |
| `attention` | 6 | 10 | once | 卡住（stuck）或需要用户注意 | 举手、担心或轻提醒，不要惊恐或连续抖动 |
| `offline` | 1 | 1 | static | 连接离线 | 单帧即可辨认“休息/断连”，不依赖动画 |

可选动作 `greet`、`wake`、`notify` 未提供时，运行时会回退：`greet`/`wake` 回退到 `idle`，`notify` 回退到 `attention`，且都按单次播放处理。现阶段不建议额外做，先保证 11 个标准动作质量。

另外注意：`walk-left` / `walk-right` 不在支持列表中，不要生成。

## 4. 显示尺寸（设计时的参考）

应用中 `PetAvatar` 的默认显示尺寸为 96 px，快捷设置里为 82 px，事件卡片里为 64 px。因此角色要在 96 px 下依然清楚：眼睛、嘴巴、各状态的姿势差异都必须看得清。建议设计时用 96 px 预览做最终检查，而不是只看 256 px 原图。

## 5. manifest.json 模板

```json
{
  "schemaVersion": 1,
  "id": "mint-pip",
  "name": "薄荷皮皮",
  "author": "作者或生成工具",
  "frameSize": { "width": 256, "height": 256 },
  "anchor": { "x": 128, "y": 224 },
  "direction": "right",
  "animations": {
    "idle":      { "frames": 8, "fps": 8,  "loop": true },
    "walk":      { "frames": 8, "fps": 12, "loop": true },
    "sleep":     { "frames": 6, "fps": 6,  "loop": true },
    "drag":      { "frames": 2, "fps": 8,  "loop": true },
    "drop":      { "frames": 6, "fps": 12, "loop": false },
    "pet":       { "frames": 6, "fps": 12, "loop": false },
    "work":      { "frames": 8, "fps": 12, "loop": true },
    "think":     { "frames": 6, "fps": 10, "loop": true },
    "done":      { "frames": 8, "fps": 12, "loop": false },
    "attention": { "frames": 6, "fps": 10, "loop": false },
    "offline":   { "frames": 1, "fps": 1,  "loop": false }
  }
}
```

注意：`offline` 的 `fps` 必须是 1–60 之间的数，这里填 1；`loop` 填 false 即可，它本身是静态单帧。帧数上限是 64。`id` 必须与目录名一致。不允许出现 http、https、绝对路径或 `../`。

## 6. 设计一致性规则

- 先定一张标准母版 `idle/0001.png`，所有其他动作都从这张母版派生，不要每帧重新画角色。
- 角色分层：头、身体、耳朵、四肢、尾巴、表情、道具。动作只改变必要图层。
- 耳朵必须与头部连成一个轮廓，不要做成独立浮动的部件。
- 角色总高度在 idle、walk、work、think 等站立动作中保持一致，只允许身体起伏在 ±4 px 以内。
- 线宽、描边颜色、阴影方向、配色在所有帧一致。
- 循环动作先画首帧、中间帧和末帧，再补中间过渡；末帧要能自然接回首帧。
- 状态差异优先用姿势和表情表达，道具只作辅助；缩到 96 px 仍能区分 `work`、`think`、`attention`、`done`。
- `sleep` 与 `offline` 要保留与站立时相近的身体比例，区别靠闭眼、趴伏、灰度或小标记，而不是把身体压扁。

技术要求：

## 8. 验收清单

- [ ] 所有帧 256×256，RGBA，透明背景，没有白底、场景、阴影贴片。
- [ ] 11 个标准动作齐全，帧数与 manifest 完全一致，编号连续从 0001 开始。
- [ ] 站立类帧的脚底中心稳定在 (128,224)，画布未被逐帧裁剪。
- [ ] 角色比例、线宽、配色、光源在所有动作中一致；耳朵与头部一体。
- [ ] `sleep` 与 `offline` 的身体比例与站立时接近，没有被压扁。
- [ ] 默认朝右，无只在右侧出现的文字或不对称道具。
- [ ] 循环动作首尾衔接；单次动作末帧稳定。
- [ ] 96 px 下 `work`、`think`、`attention`、`done` 的状态可辨认。
- [ ] manifest 的 id 与目录一致，无远程 URL、绝对路径或 `../`；`index.json` 已登记。
- [ ] `preview.png` 存在。

## 9. 与 1.0 模板的差异说明

1.0 模板里 `offline` 的 fps 写的是“—”，实际 manifest 必须填数字，这里统一为 1。1.0 中“可选动作”的回退规则与代码一致，无需改动。本文新增了触发场景和设计约束，属于说明性内容，不改变兼容约定。

## 10. 验证方式（实施后）

将新皮肤放入 `public/pets/<id>/` 并更新 `index.json` 后，在应用中切换到该皮肤，依次触发运行中、思考中、完成、卡住、离线、拖拽、戳一下等状态，检查每个动作的衔接与脚底位置。也可以运行 `npm test` 中的 skin-loader 测试，确认 manifest 能被正确解析。
