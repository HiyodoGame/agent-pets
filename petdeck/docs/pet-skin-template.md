# PetDeck 宠物皮肤与帧动画模板规范

版本：1.0  
适用对象：GrokBot、画师、动画生成工具与皮肤作者  
目标：只替换素材目录即可增加或切换宠物，不修改 PetDeck 行为代码。

## 1. 交付形式

一套皮肤就是一个本地目录。PetDeck 当前只加载随应用提供的皮肤，不支持远程 URL。

```text
public/pets/
├── index.json
└── <skin-id>/
    ├── manifest.json
    ├── preview.png
    └── animations/
        ├── idle/0001.png ... 0008.png
        ├── walk/0001.png ... 0008.png
        ├── sleep/0001.png ... 0006.png
        ├── drag/0001.png ... 0002.png
        ├── drop/0001.png ... 0006.png
        ├── pet/0001.png ... 0006.png
        ├── work/0001.png ... 0008.png
        ├── think/0001.png ... 0006.png
        ├── done/0001.png ... 0008.png
        ├── attention/0001.png ... 0006.png
        └── offline/0001.png
```

`skin-id` 只能使用小写英文字母、数字和连字符，例如 `mint-pip` 或 `orange-cat-01`。不要包含空格、中文、点号或路径分隔符。

## 2. 画布与角色锚点

| 项目 | 固定要求 |
| --- | --- |
| 画布 | 每一帧均为 256×256 px |
| 格式 | 透明背景 PNG；也允许无损 WebP |
| 默认朝向 | 朝右；PetDeck 会水平镜像形成朝左动作 |
| 角色锚点 | `x=128, y=224` |
| 脚底基线 | 普通站立帧脚底中心位于 `y=224` |
| 常规安全区 | `x=28..228, y=24..224` |
| 背景 | 完全透明，不交付白底、场景、地面或方形色块 |
| 其他 | 不要水印、文字签名、边框、外置阴影贴片或裁切透明边 |

所有帧必须保留完整画布，不要按角色包围盒自动裁剪。角色比例、线宽、颜色和光源在同一皮肤内保持一致。耳朵、尾巴、四肢和道具不能被画布裁切。`drop` 等动作可以改变角色位置，但最终落地帧必须回到统一脚底基线。

## 3. 标准动作

完整皮肤必须提供以下 11 个动作。帧数、帧率和播放方式属于兼容约定，不要随意改变。

| action | 帧数 | fps | 播放 | 内容要求 |
| --- | ---: | ---: | --- | --- |
| `idle` | 8 | 8 | loop | 安静呼吸与偶尔眨眼；首尾自然衔接，不要持续跳动 |
| `walk` | 8 | 12 | loop | 原地踏步循环，左右脚交替；实际位移由应用控制 |
| `sleep` | 6 | 6 | loop | 放松趴伏、闭眼、缓慢呼吸；不要高频闪烁 |
| `drag` | 2 | 8 | loop | 被轻轻提起，四肢离开基线，表情清楚但不过度痛苦 |
| `drop` | 6 | 12 | once | 下落、落地、轻微回弹；末帧回到稳定站立 |
| `pet` | 6 | 12 | once | 摸头/轻戳后的开心回应，可加入少量爱心或腮红 |
| `work` | 8 | 12 | loop | 专注工作，小幅爪子/工具动作，不要大幅蹦跳 |
| `think` | 6 | 10 | loop | 思考、眼神上移或轻点下巴，动作克制 |
| `done` | 8 | 12 | once | 完成后的短时开心庆祝，最后自然回到稳定姿势 |
| `attention` | 6 | 10 | once | 担心、举手或轻提醒；不要惊恐、闪烁或连续抖动 |
| `offline` | 1 | — | static | 离线静态姿势，必须仅靠静帧也能辨认休息/断连感 |

### 可选动作

| action | 建议帧数 | fps | 播放 | 未提供时回退 |
| --- | ---: | ---: | --- | --- |
| `greet` | 6 | 12 | once | `idle` |
| `wake` | 4 | 12 | once | `idle` |
| `notify` | 6 | 12 | once | `attention` |

左右朝向由应用对标准 `walk` 动作做水平镜像。当前运行时不支持 `walk-left` / `walk-right`，不要在 manifest 中添加这两个动作。

## 4. manifest.json

```json
{
  "schemaVersion": 1,
  "id": "mint-pip",
  "name": "薄荷皮皮",
  "author": "作者或生成工具",
  "frameSize": { "width": 256, "height": 256 },
  "anchor": { "x": 128, "y": 224 },
  "direction": "right",
  "animations": {
    "idle": { "frames": 8, "fps": 8, "loop": true },
    "walk": { "frames": 8, "fps": 12, "loop": true },
    "sleep": { "frames": 6, "fps": 6, "loop": true },
    "drag": { "frames": 2, "fps": 8, "loop": true },
    "drop": { "frames": 6, "fps": 12, "loop": false },
    "pet": { "frames": 6, "fps": 12, "loop": false },
    "work": { "frames": 8, "fps": 12, "loop": true },
    "think": { "frames": 6, "fps": 10, "loop": true },
    "done": { "frames": 8, "fps": 12, "loop": false },
    "attention": { "frames": 6, "fps": 10, "loop": false },
    "offline": { "frames": 1, "fps": 1, "loop": false }
  }
}
```

帧路径由 `action + 四位序号` 推导，例如 `idle` 第 1 帧固定为 `animations/idle/0001.png`。使用 WebP 时，在动作中增加 `"extension": "webp"`；一套动作只能使用一种扩展名。manifest 中不允许填写 HTTP、HTTPS、绝对路径或 `../` 路径。

`preview.png` 同样为 256×256 透明图，通常使用 `idle/0001` 的稳定姿势。`index.json` 示例：

```json
{
  "schemaVersion": 1,
  "skins": ["default", "mint-pip"]
}
```

## 5. 可直接交给 GrokBot 的生成提示词

```text
请为 PetDeck 生成一套原创 2D 桌面宠物帧动画素材，并严格按以下规范输出，不要使用任何已有 IP 或竞品角色。

角色设定：[在这里填写物种、性格、主色、标志物；例如“薄荷绿色的小猫机器人，圆润、安静、聪明，额头有小叶片”]。
画风：统一、简洁、适合缩小到 96–128 px 后观看；轮廓清晰，颜色与线条在所有帧保持一致。

每一帧必须是 256×256 px、透明背景 PNG，完整保留画布，不自动裁剪。角色默认朝右。统一角色锚点为 (128,224)，普通站立帧脚底中心在 y=224。常规角色位于 x=28..228、y=24..224 内，任何帧都不得裁切耳朵、尾巴、四肢或道具。不要背景、地面、文字、水印、边框和外置阴影。

请生成以下动作，并按 animations/<action>/0001.png 开始的四位序号连续命名：
idle：8 帧，8fps，循环，轻微呼吸和自然眨眼；
walk：8 帧，12fps，循环，原地踏步，不主动位移；
sleep：6 帧，6fps，循环，闭眼趴伏和缓慢呼吸；
drag：2 帧，8fps，循环，被轻轻提起；
drop：6 帧，12fps，单次，下落后落地并回到基线；
pet：6 帧，12fps，单次，被摸头后开心回应；
work：8 帧，12fps，循环，安静专注地工作；
think：6 帧，10fps，循环，克制地思考；
done：8 帧，12fps，单次，短时开心庆祝；
attention：6 帧，10fps，单次，温和地提醒用户；
offline：1 帧，静态离线与休息姿势。

同一动作的首尾循环必须自然，角色身体比例、脚底位置、脸部特征、颜色和线宽不得逐帧漂移。请同时输出 preview.png 和符合规范的 manifest.json，并在交付前逐帧检查透明通道、尺寸、连续编号和锚点。
```

## 6. 动画一致性建议

- 先制作一张标准 `idle/0001.png`，后续所有帧都从同一角色母版修改，不要每帧重新设计角色。
- 将头、身体、四肢、尾巴、表情和装饰分层；动作只改变必要图层。
- 循环动作先设计首帧、中间帧和末帧，再补中间过渡；末帧应能自然接回首帧。
- 眨眼只改变眼部，不要让整个头部变形。走路只改变腿部、轻微身体起伏和尾部，不改变角色总高度。
- 缩小到 25% 预览仍能看清眼睛、嘴巴和状态差异；不要依赖细纹理表达状态。

## 7. 交付验收清单

- [ ] 所有帧都是 256×256，透明通道有效，没有白底或场景。
- [ ] 11 个标准动作齐全，帧数与 manifest 完全一致，序号连续且无缺帧。
- [ ] 普通站立帧的脚底中心保持 `(128,224)`，画布没有逐帧裁剪。
- [ ] 角色比例、颜色、线宽、装饰和光源在所有动作中一致。
- [ ] 默认朝右，向左由应用镜像后没有文字或不对称道具错误。
- [ ] 循环动作首尾自然；单次动作末帧稳定，没有突然消失。
- [ ] 96 px 显示时表情与状态仍清楚，无高频闪烁、剧烈抖动或持续大幅跳跃。
- [ ] `manifest.json` 的 id 与目录一致，没有远程 URL、绝对路径或 `../`。
- [ ] `preview.png` 存在且能代表该皮肤；`index.json` 已登记皮肤 id。

## 8. 常见失败与修正

| 问题 | 原因 | 修正 |
| --- | --- | --- |
| 宠物播放时左右跳动 | 每帧自动裁剪或锚点变化 | 恢复 256×256 完整画布，统一 `(128,224)` |
| 越走越矮/脸不断变化 | 每帧重新生成角色 | 使用同一分层母版，仅修改动作图层 |
| 出现白块或黑底 | 透明通道丢失 | 导出 RGBA PNG 并检查 alpha |
| 循环最后一帧突然跳回 | 首尾姿势差距过大 | 补齐回到首帧的过渡帧 |
| 换肤后宠物空白 | 缺帧、编号从 0 开始或 manifest id 不一致 | 按目录规范修正；运行时会回退默认皮肤 |
| 缩小后看不清状态 | 细节太多、表情差异太弱 | 放大关键表情和姿势差异，减少纹理 |
