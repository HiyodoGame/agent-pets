## Persona

**阿哲**，用 10+ 个各有所长的 AI Agent 跑整条产品线的 OPC（一人公司）开发者（代表画像，锚定用户本人）

- **情境**：多个项目并行、多个 Agent 同时在后台执行任务，而他正在做别的事（写文案、做设计、休息）
- **目标**：用余光掌握所有项目/Agent 状态，不用一直盯窗口；任务接力时不用手动重新打包上下文、产物和指令
- **当前 workaround**：切窗口盯进度、翻终端日志、等弹窗；在 Agent 之间手动复制粘贴提示词/上下文/素材，充当人肉消息总线
- **挫败感**：并行看不过来；每次接力手动序列化上下文；各厂桌宠互不相通、桌面变宠物园；完成/卡住/等拍板无人及时告知；项目全局进度无法一眼看清
- **"完成"长什么样**：多项目维护直观方便；可爱桌宠住在余光里，做其他事时扫一眼就知道会话状态，出了事才被轻拍肩膀

## 商业角度

- **为什么是现在**：Agent 专业化让「一个人 + 一群 Agent」成为 OPC 标配；大厂验证桌宠形态但各自为政；接力层无人设防
- **谁付费**：OPC 开发者本人（价格敏感但愿为省时间付费，时间即产能）
- **商业化**：Freemium 假设——监控免费获客，接力 + 项目记忆付费（待验证）
- **战略意图**：growth

## 桌上的方向

**方向 A：环境化项目管家** —— 一只宠物聚合所有 Agent 成项目→任务→会话层级，住在余光里，有事才拍肩膀
- 用户价值：不再切窗口，一眼掌握全局
- 商业价值：门槛低、MVP 快、受众广
- 最高风险假设：网页 Agent 能否暴露状态；监控红海差异化薄
- 解决：机会 #1 #2 #4

**方向 B：接力秘书** —— 宠物记得每个项目的上下文/产物/进度，交接时打包好一切，一键确认完成接力；环境化监控是壳，接力是核
- 用户价值：不再当人肉消息总线
- 商业价值：占据唯一无人设防的高优先级机会；项目记忆积累切换成本；天然付费点
- 最高风险假设：异构 Agent 上下文/产物可读、指令可注入（尤其网页形态）
- 解决：机会 #3 #5

**方向 C：管线指挥家** —— 发版→素材→部署→宣传→网站做成可复用管线模板，宠物沿管线自动接力，人只在检查点拍板
- 用户价值：从管 Agent 升级为管管线
- 商业价值：锁定最强、天花板最高
- 最高风险假设：工作流可模板化；全自动接力需深度集成 + 信任，今天都不存在
- 解决：机会 #3 #4 #5

## 我押

**方向 B** —— 接力是「高重要 + 零满足 + 无人押注」的唯一蓝海；B 可分期（MVP 先做半自动接力：宠物打包、用户确认发送），技术风险可拆；项目记忆越用越厚，形成切换成本护城河。A 不是被丢弃，而是 B 的入场体验与 MVP 第一里程碑（先跑通环境化监控 + 项目视图，再叠半自动接力）。用户描述的 outcome（余光感知）正是 B 的第一步。

## 技术 Spike 计划（1 周 · 进设计前的硬门槛）

**目标**：验证「状态可读 / 产物可拿 / 提示词可注入」在三类 Agent 形态上的可行性。

| | 状态能读吗 | 产物能拿到吗 | 提示词能注入吗 |
| --- | --- | --- | --- |
| CLI 类（Qoder / Codex） | 钩子/日志/HTTP 桥 | 会话导出/文件系统 | CLI 参数/SDK/stdin |
| 桌面应用类（kimi code / zcode） | 窗口/进程/本地存储 | 本地文件/导出 | 自动化/剪贴板/接口 |
| 网页服务类（kimi work / MiniMaxDesign） | 浏览器扩展/DOM/接口 | 下载/接口 | 浏览器自动化/接口 |

**成功标准**：每类至少跑通观察侧；至少 1 类跑通完整接力闭环（读状态→拿产物→注入下一个）。

**Spike 后决策规则**：
- 全通 → 关键假设升级为有证据，进 /brief，MVP 含半自动接力
- 仅观察侧通 → MVP 先做环境化监控 + 项目视图（A 壳），接力降级为剪贴板辅助半自动，继续攻注入侧
- 网页 Agent 受阻 → 浏览器扩展或手动 check-in 兜底，明确标注覆盖边界，不承诺全适配
